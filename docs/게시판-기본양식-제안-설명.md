# 사례 게시판 본문 기본값 제안 (2026-09-29)

붙여 넣을 양식은 `게시판-기본양식-제안.md`. 관리자 화면 Administration → Content → Post types → 사례 글 종류 → Content 필드 기본값에 넣는다. 제목 칸 안내문(placeholder)도 같이 바꾼다.

제목 칸 안내문: `도구 이름 + 무엇을 했는지, 25~35자. 예: 클로드 코드로 주간 보고서 자동화: 40분을 5분으로`

## 지금 양식의 문제

- "소개 / 진행 방법 / 결과와 배운 점" 소제목은 검색어가 하나도 없다. 185편에서 순위가 오른 글은 소제목 2~3개에 도구명과 작업어가 있었다.
- 안내문이 본문보다 길어서 "(내용 입력)"과 "Tip:"이 그대로 남은 채 올라온 글이 있다.
- 첫 문단 안내가 없다. 베터모드는 본문 앞부분을 검색 결과 설명문으로 쓰고 발행 뒤 못 바꾼다. 지금 양식대로면 설명문이 "소개 시도하고자 했던 것과 그 이유를 알려주세요"가 된다.
- 숫자·날짜·결과물 링크·막힌 순간을 묻지 않는다. AI 답변이 인용하는 건 이 넷이다.

## 새 양식이 지키는 것

| 항목 | 근거 |
|---|---|
| 첫 문단 120자, 도구+한 일+숫자+날짜 | 구글 상위 300페이지 설명문 100~120자, 정의형·답형 첫 문장 |
| 소제목에 [도구]·[무엇] 자리 | 상위권 H2 5~7개 중 2~3개에 검색어. 틀 이름 소제목("소개")은 8~10위 |
| 보낸 말 원문 코드블록 | AI 인용 연구 2편: 원문·구체 수치·재현 가능한 순서가 인용됨 |
| 막힌 순간 절 | 185편 베스트 사례 공통 재료. 사람이 쓴 글로 읽히는 신호 |
| 결과: 숫자로 | 전후 숫자가 있는 글의 클릭 중앙값이 없는 글의 3배 |
| 아직 안 된 것 | 과장 없는 글 신호. "도움이 필요한 부분"은 여기로 흡수 |
| 본인 소개는 첫 소제목 아래 | 작성자 신호는 첫 문단이 아니라 본문 안에. 첫 문단은 설명문 자리 |
| 표 없음, 목록만 | 베터모드에서 표가 깨짐 |

## 양식과 write-post 스킬의 관계

스킬로 쓴 글은 이 양식을 전체 선택해 지우고 붙여 넣는다(스킬 마무리 메시지에 그렇게 안내). 스킬이 만드는 글은 같은 재료를 같은 순서로 담되 소제목을 실제 내용으로 채운다. 그래서 두 경로의 글이 같은 구조가 된다.

직접 쓰는 멤버는 대괄호와 괄호 안내를 지우고 채운다. 남으면 그대로 올라가니, 안내문은 짧게 두고 "없으면 이 절은 지워요"를 붙였다.
