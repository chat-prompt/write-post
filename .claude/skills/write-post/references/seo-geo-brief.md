# 검색·AI 인용 브리프 (사례글용)

지피터스 SEO·GEO 플레이북과 2026-09-18 지피터스 사례글 222편 분석을 사례글에 맞게 줄였다. 스터디 멤버용으로 2026-09-23 7절(한 주 수백 편일 때)을 더했다.

## 0. 데이터가 말한 것 (지피터스 사례글 222편, 2026년 3월부터 9월)

- 발행 5주 지난 165편 중 클릭 100 이상은 21편(13%), 클릭 2 이하는 59편(36%).
- 상위와 하위를 가른 건 본문 구조가 아니라 **제목이 검색어인가**였다. 수치 밀도, 1인칭 비율, 글 길이, 템플릿 사용 여부는 세 그룹이 거의 같았다.
- 제목에 한글+영문 도구명이 있는 비율: 상위 76%, 하위 42%. 제목이 도구명으로 시작하는 비율: 67% 대 37%.
- 상위 글에 실제로 들어온 검색어: "클로드 카드뉴스", "힉스필드 요금제", "omc", "인스타툰 ai", "hermes agent 후기". 제목에 그 단어가 그대로 있다.
- 하위 글 제목: "훔쳐보기", "기억이 사는 집", "3단 배선", "깨달은 것 (1부)". 쓴 사람에게는 재밌지만 아무도 검색창에 치지 않는다.
- AI 답변 엔진 경유 유입이 5건 이상인 글은 7편뿐. 전부 "도구명 + 만들기/가격/연결" 제목에 첫 문장이 정의나 답이었다.

## 1. 제목 규칙

- 검색어(도구명 + 의도)가 앞에. 예: "힉스필드(Higgsfield) 요금제 정리: 크레딧 계산과 결제 전 확인 4가지"
- 스터디 베스트 사례 185편에서는 도구명으로 시작하는 제목, 도구 두 개를 조합한 제목이 가장 강했고 제목 속 숫자는 차이가 없었다. 세부 규칙은 `best-cases-185.md` 3절이 이 절보다 우선한다.
- 의도 단어는 여섯 가지 중 하나: 사용법 · 가격/요금제 · 자동화/만들기 · 설정/연결 · 비교 · 뜻. ("후기·써보기" 같은 소감형은 구글 상위권에서 드물다, `google-top300.md`)
- 기수 머리말("[24기 ○○스터디]"), 시리즈 번호, 나만 아는 별명은 제목에서 빼고 본문으로 내린다. 기수·스터디는 태그가 맡는다.
- **길이 정본: 25~35자 목표, 45자 권장 상한, 50자 절대 상한.** 물음표·느낌표는 1개 이하. 줄표 대신 콜론.

## 2. 리드(첫 문단) 규칙

베터모드는 본문 앞 200자를 메타 설명으로 잘라 쓰고, 발행 후 못 바꾼다(2026-08 실측). 구글이 검색어에 따라 다른 문장을 스니펫으로 고를 수는 있지만, 메타 설명과 AI 크롤러가 보는 요약은 이 구간이다. **길이 정본: 첫 문단 120자 목표, 150자 절대 상한**(상위권 설명문 100~120자). 검사도 150자로 본다.

- 첫 문장은 정의문 또는 답. "힉스필드 요금제는 무료 플랜과 유료 3종으로 나뉩니다."
- 150자 안에 숫자 하나, 검색어 한글+영문 한 번, 확인일(바뀌는 정보일 때).
- 작성자 소개는 여기 두지 않는다. 첫 H2 뒤나 하단.

## 3. AI가 인용하는 것

- 숫자·통계, 출처 표기, 인용문을 보강한 글이 AI 답변에 더 잘 인용된다는 벤치마크가 있다(GEO, Aggarwal 외, KDD 2024). 다만 효과 크기는 지표·검색 순위·주제마다 달라서 **보장 수치가 아니라 작성 원칙으로만** 쓴다. 숫자를 끼워 넣기 위해 지어내지 않는다.
- 셋이 먼저다, 없으면 나머지가 무의미: **온토픽**(제목이 약속한 질문에 본문이 답함), **명시적 숫자**, **본문 안 최신 날짜**.
- **H2 아래 첫 한두 문장은 그 소제목의 질문에 바로 답한다.** 앞 문단을 안 읽어도 도구·행동·결과가 보이게. AI 답변 엔진은 섹션 하나를 떼어 인용하므로 결론 → 근거 숫자·경험 순서로 쓴다. 예: "## 클로드 코드로 보고서를 자동화한 순서" 아래 첫 문장 "클로드 코드에 지난 보고서와 원본 데이터를 주고 정리·대조·초안 생성을 세 단계로 나눴어요."
- **외부 사실에는 출처와 확인일.** 직접 잰 시간·건수는 "제가 잰 것"으로 그냥 쓴다. 그러나 도구의 가격·요금제·지원 기능·버전·정책처럼 남이 정한 사실을 쓸 때는 공식 문서 링크와 확인일("2026년 10월 6일 기준")을 붙인다. 공식 출처를 못 찾으면 단정하지 않고 빼거나 [확인 필요]로 남긴다. 참고한 자료 절은 실제로 참고한 자료가 있을 때만 만든다.
- 효과 없는 것: 키워드 밀도 맞추기, 쉽게 풀어쓰기만 하기, 분량 늘리기, 포맷만 다듬기.
- 자체 데이터가 제일 세다. 남의 블로그 수치를 옮기지 말고 **직접 잰 숫자**(세션에서 나온 시간·건수·토큰)를 쓴다.

## 4. 작성자 신호

- 작성자의 이름이나 닉네임, 이 일을 직접 한 입장과 경험 근거를 적는다. "콘텐츠팀" 같은 익명은 쓰지 않는다.
- 닉네임 + 이 일을 한 입장 + 이 글과의 관련성 한두 줄. 없는 경력을 지어내지 않는다.
- 직함이 아니라 **입장**이다. "동네에서 반찬가게를 하는", "퇴사하고 1인 창업을 준비하는", "AI를 처음 써 보는 초등 교사" 모두 강한 신호다. AI가 보는 건 "이 사람이 이 문제를 직접 겪었나"다.
- 가게 이름·회사명·실명은 필요 없다. 본인이 원할 때만.
- 위치는 첫 H2 뒤 또는 글 하단. 맨 앞에 두면 메타 설명을 잡아먹는다(2026-08-10 실제 사고).

## 5. 한글·영어 병기

같은 도구가 두 표기로 따로 집계된다(프레이머 7,582 / framer 9,642 노출). 한쪽만 쓰면 노출 절반을 버린다.

- 첫 등장에 병기: `힉스필드(Higgsfield)`, `클로드 코드(Claude Code)`.
- 리드·정의문·H2처럼 읽히는 자리에. 본문 아무데나 한 번은 의미 없다.
- 한 문장 안에서 같은 단어를 두 번 병기하지는 않는다.

## 5-1. 지금 사이트(베터모드)에서 되는 것과 안 되는 것 (2026-08 실측)

- 되는 것: 게시글 본문은 서버 렌더라 크롤러가 3,000자 이상 그대로 읽는다. 글 안의 숫자·날짜·작성자·alt는 전부 크롤된다. 개발 요청 없이 글만 잘 쓰면 오늘 바로 노출된다.
- 안 되는 것: JSON-LD 구조화 데이터(벗겨냄), llms.txt(효과 없음), 커스텀 HTML 블록(크롤러가 못 읽음), 표(셀이 붙음). 이런 데 시간 쓰지 않는다.
- 이미지 속 글자는 읽힌다고 가정할 수 없다. 카드·캡처에 넣은 숫자와 도구명은 본문 텍스트에도 쓴다(포털 이전 크롤 스펙에서 확정한 기준).
- 사이트가 날짜를 "3달 전"처럼 상대 표기로 보여주고 마크업도 비표준이라, **본문 안 절대 날짜**가 AI에겐 유일한 날짜 신호다.
- 도구 뉴스는 많은데 "AI 툴 추천" 질문에서 인용이 0건이었다. 개별 도구 글은 인용되므로, 사례글은 **한 도구를 깊게** 쓰는 쪽이 맞고 취합·비교는 별도 글의 몫이다.

## 6. 검색어 조사 (스킬이 한다, 멤버에게 묻지 않는다)

1. DEVLOG의 도구명·기능명을 한글·영문으로 뽑는다.
2. 같은 주에 올라온 글부터 본다. `node <skill>/scripts/find-recent-titles.mjs "도구A" "도구B"`로 게시판 최근 글 제목(기본 14일)을 가져와 도구 조합 + 작업 명사가 같은 제목이 있는지 본다. 방금 올라온 글은 구글에 아직 없어서 `site:` 검색만으로는 못 잡는다. 그다음 `site:gpters.org 도구명 업무`로 색인된 글을 확인한다(7절). 같은 의도의 글이 있으면 이번 글은 다른 의도(예: 사용법 대신 설정, 후기 대신 비교)나 다른 대상으로 튼다.
3. `도구명 사용법`, `도구명 자동화`, `도구명 설정` 같은 조합을 검색해 상위 글 제목 패턴을 본다.
4. 제목 후보 3개를 만든다. 도구명(조합) 앞 + 작업 명사 + 대상(`best-cases-185.md` 3절, 7절). 멤버는 고르기만 한다.
5. 어느 조합도 검색 결과에 관련 글이 거의 없으면 내부적으로 rules.md 6절(도구로 다시 잡기 → 기록형)로 간다. 이 조사는 **검색 의도·경쟁 확인**이지 검색량 확인이 아니다. 관련 결과가 적다고 수요가 없다고 단정하지 않는다. 실제 수요는 GSC·구글 트렌드·네이버 데이터랩이 있을 때만 판단한다. 이 내부 판단은 멤버용 발행메모에 쓰지 않는다.
6. 검색 도구가 없는 환경(웹 검색이 꺼진 코덱스 등)이면 2·3단계를 건너뛰고 1절·7절 공식만으로 제목을 만든다. 멤버에게 검색 조사 여부를 따로 알리지 않는다.

## 7. 한 주에 수백 편이 올라올 때 (스터디 기간)

스터디 기간에는 이 스킬로 한 주 200~300편이 올라온다. 한 편만 보면 맞는 규칙도 수백 편이 같이 따르면 서로를 깎는다.

**제목끼리 겹치지 않게**

- "클로드 코드(Claude Code) 사용법"처럼 도구명 + 의도만으로 끝나는 제목은 한 주에 수십 개가 나온다. 구글은 같은 사이트의 비슷한 글 중 하나만 보여준다. 나머지는 묻힌다.
- 제목 공식: **도구명(조합) + 작업 명사 + 구체적 대상.** 대상·업무가 제목을 가른다. 숫자는 선택.
  - ❌ "클로드 코드 사용법: 업무 자동화 후기"
  - ⭕ "클로드 코드로 세금계산서 엑셀 정리 자동화"
  - ⭕ "챗GPT로 반찬가게 인스타 문구 한 달 치 만들기"
- 대상·업무 단어는 멤버의 입장(프로필)과 DEVLOG에서 가져온다. 업종·대상이 들어가면 자연스럽게 겹치지 않는다.
- `site:gpters.org 도구명 업무`에서 **같은 도구 + 같은 업무** 글이 이미 있으면, 의도(설정·비교·가격·후기)나 대상(업종·규모)을 틀어 다른 질문에 답하게 한다.

**틀 흔적이 남지 않게**

- 모든 글이 "📝 한줄 요약 / 🎯 이런 분들께 도움돼요 / 😫 문제 상황"으로 시작하면 수백 편이 같은 뼈대가 된다. 검색엔진은 틀로 찍어낸 글을 대량 생성 콘텐츠로 보고 사이트 전체를 낮출 수 있다.
- 그래서 **소제목은 틀에서 가져오지 않고 그 글의 내용으로 쓴다.** 독자가 검색할 질문이나 그 섹션의 결론이 소제목이 된다. "세금계산서 파일명이 제각각일 때 어떻게 묶었나", "40분이 3분이 된 이유".
- 게시판 기본 틀(소개 / 진행 방법 / 결과와 배운 점)을 쓰더라도 이름 뒤에 내용을 붙인다. 2026년 9월 기준 베스트 사례 185편 중 81편이 이 틀 이름만 달고 있었다.
- 구성(스토리텔링·비교·튜토리얼·짧은 후기)은 글 내용에 맞춰 고른다. 늘 같은 구성을 쓰지 않는다.

**주차 과제 연재**

- 같은 프로젝트를 주마다 이어 쓰는 글이 많다. 주차 표기("[2주차 과제]")는 제목이 아니라 본문 첫 소제목 아래에. 제목은 그 주에 새로 한 일로 검색어 공식을 따른다.
- 지난 글을 링크하고 이번 주에 달라진 것부터 쓴다. 두 글이 같은 검색어를 두고 다투지 않게 의도나 대상을 바꾼다(1주차 "만들기", 2주차 "연결·설정", 3주차 "비교·운영").
- 다음 편 예고나 전체 편수는 쓰지 않는다. 계획이 바뀌면 약속이 거짓이 된다.

**참고한 자료**

- 베스트 사례 185편 중 64편에 게시판 틀의 "도움 받은 글" 칸이 있었지만, 링크가 든 건 22편이고 지피터스 글 링크는 3편뿐이었다. 대부분 공식 문서였고, 나머지는 강의·사람에 대한 감사나 빈칸이었다.
- 그래서 "참고한 자료"로 넓혀 받고, 없으면 섹션을 만들지 않는다. 공식 문서 링크는 AI가 보는 출처 신호가 된다.
- 글마다 다른 것: 직접 잰 숫자, 실제 캡처, 막힌 지점, 멤버의 입장. 이 넷이 있으면 틀이 비슷해도 다른 글이다. 넷 다 없으면 쓰지 않는 게 낫다.
