# 베스트 사례 185편에서 배운 것

2026년 9월 23일, 지피터스 AI스터디 19·20·21·23기 베스트 사례 185편을 전문으로 읽고, 구글 서치 콘솔 성과(2025년 11월부터 2026년 9월까지 클릭·노출·검색어)와 맞춰 봤다. 초안을 쓰기 전에 이 문서를 읽는다. 괄호 안 번호는 기수-순번이다.

## 1. 사람이 쓴 글로 읽히는 것

**잘 읽힌 글에 늘 있던 것**

- **작성자의 사정이 끝까지 이어진다.** 고양이 이름과 발표 전날 화면이 깨진 일(23-5), 교회 번역팀의 수작업 9단계(21-48), 대만에서 와 아동복 수출을 하는 본업(21-4), 아들과 아들 친구들(21-17). 무엇이 걸려 있었는지가 보이면 끝까지 읽힌다.
- **AI에게 친 말을 다듬지 않고 옮긴다.** "스큐류가 너무 작아서 그런가"(23-5), "115200을 누르니까 IDE가 거의 멈춘거처럼 흰 창이 나오네"(23-56). 오타까지 살아 있는 요청이 가장 사람 같다.
- **막힌 순간의 감정과 그때 바꾼 한 가지.** "최악이다"(23-10), "이 순간 진짜 울컥했어요"(21-4), "또 실패할까봐 너무 조마조마 했습니다 // 근데 성공이었어요"(19-20). 시도 횟수를 센 글(19-20의 1번째부터 6번째, 19-6의 "배포 에러해결을 21회 시도했으나 결국은 실패")은 긴장이 쌓인다.
- **모르는 걸 모른다고, 안 된 걸 안 됐다고 쓴다.** "lint가 없대요? (그게 모지;;;;;)"(23-12), "솔직하게, 아직 안 된 것들"(23-5), "실제 결제는 아직 못 받습니다"(23-18), "현재 완성도는 스스로 7점 정도"(21-18). 이 한 줄이 글 전체의 신뢰를 올린다.
- **자기 착각을 인정한다.** "알고 보니 내가 헷갈렸던 것"(21-21), "1단계에서 제가 만든 문서가 틀렸다"(23-53), "위험을 만들어놓고 그 위험을 설명하는 주석을 정성껏 붙인 셈"(23-42).
- **괄호 속 혼잣말과 작은 유머.** "(마지막 줄 왠지 킹받아.... 😡)"(23-12), "※ 절대로 End of Document를 실수로 입력한 거 아님"(21-15), "(마누스는 잘못 없다)"(21-35).

**지치게 하거나 AI가 쓴 티가 난 것**

- **틀의 빈칸을 추상어로 채움.** 예전 write-post 틀(📝 한줄 요약, 🎯 이런 분들께, 🌍 다른 업무에 적용한다면?)을 쓴 글이 23기 63편 중 14편이었다. 칸마다 구체적 사건이 들어간 글(23-7, 23-10, 23-46)은 읽혔고, 교훈만 채운 글(23-59 "화면 범위 결정의 중요성")은 지쳤다. "🌍 다른 업무에 적용한다면?"은 거의 모든 글에서 뻔한 채움글이었다.
- **"A와 B는 다르다" 맺음말.** 23기에서만 10편 가까이 반복됐다. "조용한 것과 안전한 것은 다르다", "'만들었다'와 '돈다'는 다릅니다".
- **AI 출력 통째 붙이기.** 6만 자 중 대부분이 Gem 대화(21-39), 커서 계획 md가 본문 대부분(19-12), ChatGPT 에필로그 그대로(20-24). 붙일수록 작성자가 사라진다.
- **3인칭·AI 시점이 새어 나옴.** "이유를 물었더니 답은 짧고 명확했습니다"(23-33, 작성자가 자기를 인용), "사용자가 '전체 기간 엑셀 1개로 되는데?'라고 지적했습니다"(23-21, AI 1인칭), "은영님이 대화 중에 말씀하신"(23-51, 봇이 쓴 요약).
- **발행본에 남은 초안 찌꺼기.** "(내용 입력)", "Tip: 사용한 프롬프트 전문을 꼭 포함하고", "📸 [이미지 삽입 위치 1: …]"(21-49에 5번), "[본인이 채워주세요: …]"(23-3), 스킬이 붙인 "📌 게시판 업로드 안내"와 "추천 이미지"(21-9). 185편 중 39편(21%)에 이런 흔적이 있었다.
- **근거 없는 숫자와 서로 안 맞는 숫자.** "ROI: 5,000%", "99.9% 안정성", "완전 무인 운영"인데 카톡은 Mock 발송(20-19). 제목 "30분 만에"와 본문 "약 2시간"(19-13). 표마다 40명과 42명(23-62).
- **결과보다 긴 미래 계획.** 단기·중기·장기·궁극 계획(21-11).

## 2. 과정과 결과를 제대로 담은 글에 있던 것

따라 할 수 있었던 글(21-48, 23-10, 23-47, 21-21, 20-29, 19-28)에는 아래가 거의 다 있었고, 약한 글은 대부분 빠져 있었다. 스킬은 이 여덟 가지를 **세션에서 먼저 뽑고, 빈 것만 묻는다.**

1. **처음 보낸 요청 원문.** 다듬지 않은 말투. 약한 글의 가장 흔한 누락이다("첫 실전 요청은 아주 짧았습니다"라고만 쓴 23-40).
2. **막힌 순간의 원문.** 에러 문구("Detected linked project does not have \"id\"", 23-48)나 AI의 엉뚱한 답(Genspark가 "구현 불가능한 기능들"이라며 거절한 원문, 19-27).
3. **방향을 바꾼 한 마디와 그 결과.** Selenium에서 API 직접 호출로(19-23), 올인원에서 FFmpeg 합성으로(21-2), `--schedule`을 `--cron`으로(21-49).
4. **전후 숫자, 그리고 잰 것인지 기대치인지.** "매주 1~2시간에서 0분"(21-48), "인식률 14%에서 75%"(23-5). "연간 약 100일 절약 기대"라면서 첫 실행은 예정인 글(21-20)은 기대치를 실측처럼 썼다.
5. **걸린 시간과 쓴 돈, 요금제.** "6일(실작업 3일)", "$1.53 폐기분, $22.14 최종본"(23-10), "약 $2.1"(20-32). 185편 중 비용을 적은 글은 열 편 남짓이었다.
6. **도구·모델 이름과 버전.** "Sonnet 4.6"(21-21), "Hermes v0.20.0"(23-1), 드라이버를 "3.9에서 3.7로 내림"(23-26). 대부분 빠져 있었다.
7. **결과물 실물.** 링크(배포 주소, GitHub, 유튜브, 플레이 URL)와 **이미지 없이도 이해되는 결과 묘사 한두 줄.** "다음과 같은 결과물이 나왔습니다" 다음이 비어 있는 글(20-31)은 이미지가 깨지면 결과가 없다.
8. **아직 안 되는 것.** 20-32의 "현재 상태", 23-5의 "솔직하게, 아직 안 된 것들".

더 있으면 좋은 것: 처음 써 본 사람의 반응("이게 진짜 돼요?", 21-18), 이미지마다 한 줄 캡션("그림 1." 형식, 23-2).

**외부 독자가 따라 할 수 없는 글**: 스터디 단톡방·스터디 제공 파일이 있어야 재현되는 글(20-21, 20-35, 20-13). 무엇이었는지 한 줄로 설명하거나, 공개된 대안을 적는다.

**보안**: 서버 IP와 포트(19-22), 채팅방 ID(19-4)가 발행본에 있었다.

## 3. 구글에서 클릭을 받은 글

185편의 클릭 합계 6,316. 1위 한 편이 1,861(29%), 상위 10편이 약 68%. 클릭 0이 43편. 19·20·21기(발행 5개월 이상) 122편 기준으로 클릭 중앙값을 비교했다.

- 제목이 도구명으로 시작: **52.5** / 아니면 4.5
- 제목에 도구 두 개 이상(조합): **47** / 아니면 6
- 제목에 도구명 하나 이상: **20.5** / 아니면 2.5
- 제목에 숫자: 6.5 / 아니면 7 (차이 없음)
- 이미지 5장 이상: 6.5 / 아니면 7 (차이 없음)
- 본문 5,000자 이상: 15 / 아니면 5 (중앙값은 오르지만 1위는 1,262자, 23기 1위는 857자)

**실제로 클릭을 만든 검색어**는 거의 다 도구 조합이거나 도구 + 작업이었다: "클로드 ppt 스킬"(284클릭), "blender mcp codex", "코덱스 블렌더 mcp", "안티그래비티 제미나이", "헤르메스 제미나이", "옵시디언 구글 캘린더", "메타 광고 라이브러리 api", "네이버 부동산 mcp", "스티치 안티그래비티", "claude gh".

**규칙으로 쓸 수 있는 것**

1. **제목 앞 15~20자에 도구명(한글).** 도구가 둘이면 둘 다. "헤르메스에 제미나이 Notebook 연동하기"(23-28, 857자로 51클릭).
2. **도구 뒤에는 사람들이 치는 작업 명사.** 연동, 만들기, 자동화, 크롤링, 사용법, 설정, 비교. 대상이 대중적이면 더 크다: "네이버 부동산"(21-21, 451클릭), "스마트스토어 상세페이지 HTML"(23-47).
3. **비유·말장난·감성형 제목은 0에 가깝다.** "산타의 귀환", "볼트 대 이사의 날", "선풍기에 영혼 불어넣기", "수레바퀴를 다시 발명하지 말라"(관용구 검색에만 걸려 235노출에 2클릭). 재밌는 문장은 첫 문단으로 내린다.
4. **직접 지은 이름은 일반 명사와 함께.** "판돌이"(엉뚱한 "판돌이 뜻"에 걸림), "EduVibe", "마케팅 캡틴", "jeonse-guard". 제목에는 "전세사기 확인 앱"처럼 무엇인지를 쓴다.
5. **기수·주차·연재 표기가 제목 앞이면 손해.** "[21기 고마워클코]"가 핵심어 자리를 차지(21-44, 평균 순위 13.2). "23기 내업무에이전트_2주차 과제_…"(0클릭).
6. **한글과 영문을 둘 다.** 제목엔 한국어 검색 표기("클로드 코드", "코덱스", "안티그래비티"), 첫 문단엔 영문(Claude Code, Codex, Antigravity). "Claude Code"만 쓴 21-4는 "맥미니 클로드코드" 검색에 0클릭.
7. **첫 문장을 검색어 문장으로.** 1위 글의 첫 줄: "안티그래비티 터미널에서 클로드 공식 pptx 스킬을 호출해". 23-38(359클릭)의 첫 문단: "Blender MCP를 코덱스에 연결해". 공식: "[도구A]를 [도구B]에 연결해 [결과물]을 만들었어요."
8. **첫 문단에 동의어를 한 번.** 21-21은 본문에 "크롤링"과 "MCP"가 없었는데 그 검색어로 클릭이 왔다. 가져올 수 있었던 클릭을 운으로 받은 것이다. 크롤링/수집, 자동화/연동처럼 같은 뜻의 검색어를 첫 문단에 한 번씩.
9. **제목이 약속한 걸 본문이 줘야 한다.** 노출은 많은데 클릭이 적은 글은 의도가 어긋났다. "클로드 /ghost"로 433노출 4클릭(19-9, 사람들은 명령어를 찾았는데 글은 Ghost 블로그), "타입봇" 781노출(20-30, 정의를 찾는데 글은 사례). 새 도구·새 기능이면 "○○는 ○○하는 도구예요" 정의 한 줄과 "사용법"이라는 말을 넣는다(21-15는 "claude dispatch 사용법" 검색이 있었는데 본문에 "사용법"이 0회).
10. **본문의 정확한 고유 문자열이 긴 꼬리를 만든다.** 에러 원문, API 이름, 버전, 파일명: "메신저봇 39a"(19-22), "simple_expansion"(23-11), "ch340 windows 11 driver"(23-26). 다만 저장소 이름·배포 주소도 검색된다("rnrneks" = 영문 자판으로 친 "구구단", 20-21). 의미 있는 이름을 쓴다.
11. **새 도구는 빨리 쓰는 글이 이긴다.** 결과물이 약해도 Blender MCP + 코덱스(23-38), 클로드 공식 pptx 스킬(20-9), Codex 앱(23-58)은 경쟁 글이 없을 때 올라갔다. 글의 질과 검색 성과는 따로 논다. 그래서 검색은 제목·첫 문단이 맡고, 본문은 사람을 위해 쓴다.
