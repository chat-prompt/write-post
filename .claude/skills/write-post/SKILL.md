# 지피터스 사례 게시글

스터디 멤버 수백 명이 매주 과제로 쓰는 스킬이다. 개발자가 아닌 멤버, 윈도우, 파이썬 없는 환경, 챗GPT 웹만 쓰는 멤버가 다 있다. 그래서 **멤버가 답하는 건 두 번뿐이다.** 처음 설정 한 번, 글마다 확인 한 번. 나머지는 스킬이 기록에서 뽑는다. 목표는 한 편에 5분.

```
처음 1회 설정(질문 1번) → ① 기록 읽기(자동) → ② 확인 한 번(재료표·제목·빈 칸) → ③ 초안 → 게이트 → 발행메모(자동)
```

- 단계를 시작할 때 한 줄로 알린다. 예: `지금 여기: ② 확인`
- 질문은 텍스트 번호 목록으로 한 메시지에 모아 묻는다. 질문 도구는 보기 4개 제한이 있고 코덱스 등에는 없다.
- 단계를 todo·task 목록에 올리지 않는다. 멤버 답을 기다리는 단계에서 자동 진행 훅이 반복 발동한다.
- 카드·폰 미리보기·문체 추출은 기본에서 뺐다. 멤버가 원할 때만 한다(맨 아래 "요청할 때만").

## 처음 1회 설정 (프로필이 없을 때만)

`~/.gpters/write-post/profile.json`이 있으면 건너뛴다. "프로필 다시 설정"이라고 하면 다시 연다. 네 가지를 **한 메시지**로 묻는다.

```
처음이라 네 가지만 여쭐게요. 번호 옆에 답을 적어 주세요.

1. 지피터스 닉네임 (프로필에 보이는 이름 그대로)
2. 몇 기예요? (예: 24기. 스터디가 아니면 '없음')
3. 어떤 입장에서 쓰세요? 번호 + 한 줄. 회사·가게 이름은 안 적어도 돼요.
   1) 회사에서 일해요            2) 내 가게·사업을 해요         3) 창업했거나 준비 중이에요
   4) 프리랜서·강사·크리에이터예요 5) 쉬면서 다음을 준비 중이에요   6) 학생·주부·기타
   AI는 얼마나 써 보셨어요? (처음 / 몇 달 / 1년 넘게)
4. 글 분위기
   1) 짧고 간결하게   2) 친절하고 재밌게(어요체)   3) 시크하게(습니다체, 이모지 없이)   4) 진중하게(숫자마다 출처)   5) 잘 모르겠어요
```

직함이 아니라 **입장**을 받는다. "AI 처음 써 본 사람이 해냈다"는 그 자체로 독자가 찾는 글이라 5번, 6번도 똑같이 좋은 신호다. 회사명·가게 이름·실명을 적으면 "글에는 '동네 반찬가게'처럼 쓸까요?"로 일반 명사를 제안한다.

답을 받으면 기수로 실제 스터디 태그를 가져와 **한 번 더** 묻는다(node가 없으면 "태그에 보이는 이름 그대로 적어 주세요").

```bash
node <skill>/scripts/find-tags.mjs "24기"     # → 1. 24기 GEO실험실  2. 24기 업무자동화 ...
```

```
스터디 태그를 번호로 골라 주세요: (목록)
글에는 이렇게 표기할게요. 맞으면 '네': "지피터스 24기 ○○ 멤버 (닉네임)이에요. (입장 한 줄)면서 AI를 (기간) 써 보고 있어요."
```

입장 한 줄은 "~하면서"로 이어지게 어미만 다듬는다("콘텐츠를 만들어요" → "콘텐츠를 만들면서"). 내용은 바꾸지 않는다.

저장한다. `voice.md`는 `references/voice-default.md` 전체에, 그 문서 맨 끝 "분위기 문단"에서 고른 번호의 문단 하나를 붙인 것이다. 문체 추출은 하지 않는다("요청할 때만" 참고).

```json
// ~/.gpters/write-post/profile.json
{ "nickname": "반찬엄마", "cohort_tag": "24기 GEO실험실", "stance": "2", "stance_line": "동네에서 반찬가게를 하고 있어요", "ai_experience": "몇 달", "author_line": "지피터스 24기 GEO실험실 멤버 반찬엄마예요. 동네에서 반찬가게를 하면서 AI를 석 달째 써 보고 있어요.", "tone": "2", "set_at": "2026-09-23" }
```

## ① 기록 읽기 (자동)

> 지금 여기: ① 기록 읽기

```bash
node <skill>/scripts/scan-session.mjs                 # 현재 폴더의 Claude Code 세션 → DEVLOG.md + materials.json
```

스크립트가 요청 원문(작업 중에 이어 보낸 말 포함), 막힌 순간, 그 뒤 멤버가 보낸 말, 작업 시간(30분 넘게 쉰 구간 제외), 파일 수·명령 수·에러 수, 모델·토큰, 결과물, 아직 안 된 것, 세션에서 연 자료를 뽑는다. 막힌 순간 후보가 여럿이면 **멤버가 반응한 것**(되돌린 말, AI의 정정)을 쓰고, 멤버가 반응하지 않은 도구 에러는 글감이 아니다. 원문이 잘려 보이면 `materials.json`의 긴 본문을 본다. 모델명은 한글(영문)로 쓴다: "클로드 오푸스 5(Claude Opus 5)". **node가 없거나 클로드 코드가 아닌 도구(코덱스·제미나이 CLI·오픈코드)면** `references/devlog-guide.md`대로 직접 읽어 같은 항목을 채운다. 그때 지킬 것: 큐에 쌓인 메시지도 요청이다, 압축 요약("This session is being continued…")은 원문이 아니다, 질문 도구의 자유 입력 답은 그대로 쓴다.

**세션이 없거나, 있는데 못 읽으면**(챗GPT·클로드 웹, 제미나이 앱, 또는 권한 거부로 세션 파일을 못 연 경우) 이렇게 묻는다. 세션을 못 읽었으면 그 사실을 발행메모에 적고, 요청 원문을 커밋이나 문서로 지어 채우지 않는다.

```
이 폴더에서 AI 작업 기록을 못 찾았어요. 둘 중 편한 걸로 주세요.
1. AI와 나눈 대화를 복사해서 붙여 넣기. 길어도 괜찮아요. 처음 보낸 말과 막혔던 부분이 들어가게, 
   내 말과 AI 답이 구분되게 붙여 주세요. (챗GPT 화면을 그대로 복사하면 돼요)
2. 이번에 한 일을 세 줄로 적기
```

붙여 넣은 대화는 `./chat.txt`로 저장하고 `--paste ./chat.txt`로 돌린다. 화자 구분이 안 되면 한 번 다시 부탁한다. 중간에 잘린 답이 보이면 잘린 채로 가고 DEVLOG에 "(여기서 잘림)"만 남긴다. 붙여 넣은 대화에는 날짜·걸린 시간·모델이 없다. ②에서 묻는다. 도구 이름이 대화에 안 보이면 그것도 ②에서 묻는다. 세 줄만 받았으면 DEVLOG 없이 ②로 간다.

**재료 여덟 가지** (`materials.json`의 칸. 없는 칸은 비워 두고 ②에서 묻는다. 지어내지 않는다.)

1. 처음 보낸 요청 원문: 오타·말투 그대로. 가리는 건 넷뿐이다. 사용자 이름 든 절대 경로는 `~/…`로, 로그인해야 열리는 링크는 "(구글포토 링크)"처럼 괄호 설명으로, 키·이메일·전화번호는 지우고, 남의 이름은 역할로.
2. 막힌 순간 원문: 에러 문구, AI의 엉뚱한 답이나 정정("이 영상은 세로가 아니라 가로입니다"), 멤버가 "안 돼", "다시", "이게 뭐야" 한 지점.
3. 방향을 바꾼 한 마디: 막힌 뒤 멤버가 보낸 요청. 없으면(AI가 스스로 풀었으면) 비우고 그렇게 쓴다.
4. 전후 숫자: 세션에서 잰 것과 "전에는 얼마나"(멤버에게 묻는다). 잰 것과 기대치를 구분한다.
5. 시간과 돈: 작업 시간(분 단위 반올림), 로그에 있으면 토큰, 요금제는 묻는다. 비용은 로그에 없으면 안 쓴다.
6. 도구·모델·버전.
7. 결과물 실물: 배포 주소, 저장소, 만든 파일, 그리고 이미지 없이도 읽히는 두 줄 묘사. 결과물이 로그인 뒤에만 보이면 주소 대신 "로그인하면 보이는 것" 두 줄.
8. 아직 안 되는 것: 미룬 것, 세션 끝에 남은 에러.

- 제목은 ②에서 고른 것. H1은 이것 하나.
- 첫 문장은 "[도구A]를 [도구B]에 연결해 [결과물]을 만들었어요" 꼴. 영문 표기는 여기서 괄호로: "클로드 코드(Claude Code)".
- 첫 150자에 숫자 하나와 절대 날짜("2026년 9월 23일에 한 작업"). 날짜를 모르면 "2026년 9월 28일 기준" 꼴로 정리한 날짜를. 같은 뜻의 검색어(크롤링/수집)를 한 번. 새 도구면 "○○는 ○○하는 도구예요" 정의 한 줄. 인사·작성자 소개·스터디 안내는 두지 않는다. 이 구간이 검색 결과 설명문이 되고 발행 후 못 바꾼다.
- 재미있는 한 줄은 첫 문단 둘째 줄부터.

**사람을 위한 본문**

- 작성자의 사정을 끝까지 잇는다. 첫 H2 뒤 `author_line`에서 시작한 사정이 막힌 순간과 결과에서 다시 나온다.
- **형식은 넷.** AI에게 보낸 요청은 코드블록(원문 그대로, 한 블록 8줄까지, 넘으면 보낸 메시지 단위로 나눈다). AI의 답은 인용문(`>`)으로 5줄 이하. 에러·명령 결과는 코드블록 5줄 이하, 길면 "(뒤로 4줄 더)". 맨 끝 따라 할 프롬프트는 코드블록에 [바꿀 부분] 표시.
- 막힌 순간은 원문 + 바꾼 것 + 결과. **기분 한 줄은 세션의 멤버 말이나 ②의 5번 답에서만.** 둘 다 없으면 사실만. "민망했어요", "자신 있게 넘겼는데"처럼 기록에 없는 감정·태도를 지어 넣지 않는다.
- 결과는 이미지 없이도 읽히게 링크 + 두 줄. 처음 써 본 사람 반응은 결과 절에 그 말 그대로 한 줄.
- "아직 안 된 것"을 쓴다. 앞으로의 계획은 결과보다 짧게, 없으면 안 쓴다.
- 소제목(H2)은 그 글의 내용으로. 게시판 기본 틀을 쓰면 "소개: 가계부를 슬랙으로 기록하고 싶었던 이유"처럼 내용을 붙인다.
- 이어 쓰는 글이면 첫 H2 아래 "N주차 과제로, 지난주 [지난 글 제목](주소)에서 만든 ○○에 △△를 붙였어요" 한두 줄. 다음 편 예고·전체 편수는 쓰지 않는다.
- 끝은 따라 할 프롬프트 1개 또는 3~5단계 순서. 참고한 자료가 있으면 `## 참고한 자료`, 없으면 만들지 않는다.

**쓰지 않는 것.** 교훈 격언 맺음("A와 B는 다르다"), 3인칭·AI 시점("사용자가 물었다"), 채움 섹션("다른 업무에 적용한다면?", "이런 분들께 추천"), 근거 없는 숫자와 과장(ROI, "10배", "완전 무인"), 자리표시·안내문("[이미지 1]", "(내용 입력)", 게시판 양식 질문), 줄표, 물결표 범위, 3열 이상 표, 헤지, 남이 못 여는 링크, 사용자 이름 든 경로, 서버 IP.

`./AI_CASE_STUDY.md`로 저장한다. **이 파일에는 게시판에 올릴 본문만 둔다.**

> 지금 여기: ③ 게이트

```bash
python3 <skill>/scripts/check-gate.py ./AI_CASE_STUDY.md --keyword "<도구명 한글>" --keyword-en "<영문>" --author "<닉네임>"
python3 <skill>/scripts/check-ai-tell.py ./AI_CASE_STUDY.md
```

두 스크립트 모두 종료 코드 0이 될 때까지 고치고 다시 돌린다. `[주의]`는 알리기만. python이 없으면 `references/rules.md` 4절·4-1절을 한 줄씩 직접 대조하고 "자동 검사 대신 직접 확인했어요"라고 말한다. 그다음 스킬이 직접 본다: 같은 숫자가 제목·첫 문단·본문·캡션에서 다 같은가, 제목이 약속한 것(연동·사용법·만들기)을 본문이 보여주나, 재료 여덟 가지 중 빠진 것, 요청 원문이 다듬어지지 않았나, 이미지에 경로·이메일·키·남의 이름이 없나.

## 요청할 때만

- **"카드 만들어 줘"**: 전후 숫자 비교 카드. node + playwright가 있을 때. `references/tpl-compare.html`(숫자 둘 비교)·`tpl-two-roles.html`(둘로 나누기)을 복사해 숫자와 한 줄만 바꾸고 `node <skill>/scripts/capture-card.mjs ./case-post-images/card-1.html`. 도식(`.wrap`) 폭 520~560px, 글자 28px 이상, 한 장에 생각 하나. 만든 PNG는 열어서 본다.
- **"폰으로 미리 보여 줘"**: `node <skill>/scripts/preview-mobile.mjs ./AI_CASE_STUDY.md --width 390`.
- **"내 글로 문체 뽑아 줘"**: `node <skill>/scripts/fetch-member-posts.mjs "<닉네임>" --limit 30 --out ./my-posts.json`으로 공개 글을 읽고 종결어미 비율·문장 길이·자주 쓰는 표현·도입 방식을 뽑아 `voice.md`를 다시 만든다. 3편 미만이면 기본 문체로.
- **"프로필 다시 설정"**: 처음 1회 설정을 다시.
- playwright·Pillow 설치를 먼저 권하지 않는다. 멤버가 원하면 `npm i -g playwright && npx playwright install chromium`, `pip install pillow`.

## 절대 하지 않는 것

- 검색어를 멤버에게 묻지 않는다. 스킬이 조사해 제목으로 보여준다.
- 숫자·경력·감정을 지어내지 않는다. 기록에 없고 멤버가 비우면 그것 없이 쓴다.
- 남이 못 여는 링크, 사용자 경로, 키, 남의 개인정보를 본문과 이미지에 남기지 않는다(`references/rules.md` 1~3절).
- 틀 소제목을 쓰지 않는다. 한 주 수백 편이 같은 뼈대가 되면 사이트 전체가 손해를 본다.
- 요청 원문을 다듬지 않는다. 오타와 말투가 사람이 쓴 표시다.
- 본문 파일에 메모·자리표시·안내문을 넣지 않는다. 그런 건 발행메모로.
- 무언가를 설치하라고 먼저 권하지 않는다. 없으면 대체한다.
- 발행하지 않는다. 발행메모까지가 이 스킬의 끝이다.
