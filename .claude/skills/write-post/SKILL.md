# 지피터스 사례 게시글

스터디 멤버 수백 명이 매주 과제로 쓰는 스킬이다. 개발자가 아닌 멤버, 윈도우, 파이썬 없는 환경, 챗GPT 웹만 쓰는 멤버가 다 있다. 그래서 **멤버가 답하는 건 적게.** 처음 설정 두 번(질문 세 개, 태그 고르기), 글마다 확인 한 번, 캡처를 줬으면 가릴 곳 승인 한 번. 첫 글은 최대 네 번, 두 번째 글부터는 한두 번. 나머지는 스킬이 기록에서 뽑는다. 목표는 한 편에 5~7분.

```
처음 1회 설정(질문 2번) → ① 기록 읽기(자동) → ② 확인 한 번(찾은 것·제목·빈 칸) → ③ 초안 → 점검 → 발행메모(자동)
```

- 단계를 시작할 때 한 줄로 알린다. 예: `지금 여기: ② 확인`. 멤버에게 보이는 말에는 재료표·게이트·DEVLOG·세션 같은 말 대신 "찾은 것", "점검", "작업 기록"이라고 쓴다.
- 질문은 텍스트 번호 목록으로 한 메시지에 모아 묻는다. 질문 도구는 보기 4개 제한이 있고 코덱스 등에는 없다.
- 단계를 todo·task 목록에 올리지 않는다. 멤버 답을 기다리는 단계에서 자동 진행 훅이 반복 발동한다.
- 카드·폰 미리보기·문체 추출은 기본에서 뺐다. 멤버가 원할 때만 한다(맨 아래 "요청할 때만").

## 처음 1회 설정 (프로필이 없을 때만)

`~/.gpters/write-post/profile.json`이 있으면 건너뛴다. "프로필 다시 설정"이라고 하면 다시 연다. 멤버는 10대부터 60대까지 있고 글을 써 본 적 없는 분이 많다. 그래서 **세 가지만 한 메시지**로 묻고, 말투는 묻지 않는다(기본 말투로 시작, 원하면 나중에 "말투 바꿔 줘").

```
처음이라 세 가지만 여쭐게요. 번호 옆에 답을 적어 주세요.

1. 지피터스 닉네임 (프로필에 보이는 이름 그대로)
2. 몇 기예요? (예: 24기. 스터디가 아니면 '없음')
3. 어떤 분이세요? 가까운 번호 하나 + 한 줄. 회사·가게 이름은 안 적어도 돼요.
   1) 회사에 다녀요              2) 내 가게·사업을 해요        3) 창업했거나 준비 중이에요
   4) 프리랜서·강사·크리에이터예요  5) 은퇴했거나 쉬고 있어요       6) 학생이에요
   7) 주부·기타
   AI는 얼마나 써 보셨어요? (처음 / 몇 달 / 1년 넘게)
```

직함이 아니라 **어떤 사람이 이 일을 해냈는지**를 받는다. "AI 처음 써 본 60대가 해냈다", "고등학생이 만들었다"는 그 자체로 독자가 찾는 글이라 5번, 6번, 7번도 똑같이 좋은 신호다. 회사명·가게 이름·실명을 적으면 "글에는 '동네 반찬가게'처럼 쓸까요?"로 일반 명사를 제안한다. 나이는 묻지 않는다. 본인이 말하면 "예순에 처음"처럼 본인 표현 그대로 쓴다.

답을 받으면 기수로 실제 스터디 태그를 가져와 **한 번 더** 묻는다(node가 없으면 "태그에 보이는 이름 그대로 적어 주세요").

```bash
node <skill>/scripts/find-tags.mjs "24기"     # → 1. 24기 GEO실험실  2. 24기 업무자동화 ...
```

```
스터디 태그를 번호로 골라 주세요: (목록)
글에는 이렇게 표기할게요. 맞으면 '네': "지피터스 24기 ○○ 멤버 (닉네임)이에요. (입장 한 줄)면서 AI를 (기간) 써 보고 있어요."
```

입장 한 줄은 "~하면서"로 이어지게 어미만 다듬는다("콘텐츠를 만들어요" → "콘텐츠를 만들면서"). 내용은 바꾸지 않는다.

저장한다. `voice.md`는 `references/voice-default.md`를 그대로 복사한 것이다(기본 말투: 어요체, 짧은 문단, 이모지 없이. 10대도 60대도 읽힌다). 문체 추출·말투 선택은 하지 않는다("요청할 때만" 참고).

```json
// ~/.gpters/write-post/profile.json
{ "nickname": "반찬엄마", "cohort_tag": "24기 GEO실험실", "stance": "2", "stance_line": "동네에서 반찬가게를 하고 있어요", "ai_experience": "몇 달", "author_line": "지피터스 24기 GEO실험실 멤버 반찬엄마예요. 동네에서 반찬가게를 하면서 AI를 몇 달째 써 보고 있어요.", "tone": "default", "set_at": "2026-09-23" }
```

## ① 기록 읽기 (자동)

> 지금 여기: ① 기록 읽기

```bash
node <skill>/scripts/scan-session.mjs                 # 현재 폴더의 Claude Code·Codex CLI 세션 → DEVLOG.md + materials.json
```

클로드 코드와 코덱스 기록을 한꺼번에 읽는다. 멤버가 코덱스로 작업하고 클로드 코드에서 이 스킬을 돌려도(반대도) 같은 폴더면 찾는다. 이 폴더에서 띄운 기록이 없으면 상위 폴더에서 띄운 세션 중 이 폴더를 언급한 요청만 가져온다(부모 폴더에서 AI를 열고 하위 폴더 작업을 한 경우). 기록이 5일 넘게 이어지면 **마지막 6일만** "이번 작업"으로 본다(주차 과제). 지난 주 작업까지 한 글에 넣으려면 `--window 0`. 요청이 80개를 넘으면 최근 80개만 쓰고 DEVLOG 첫 줄에 잘랐다고 적힌다. 이 스킬 자신이 돌던 세션은 자동으로 뺀다.

스크립트가 요청 원문(작업 중에 이어 보낸 말 포함), 막힌 순간, 그 뒤 멤버가 보낸 말, 작업 시간(30분 넘게 쉰 구간 제외), 파일 수·명령 수·에러 수, 모델·토큰, 결과물, 아직 안 된 것, 세션에서 연 자료를 뽑는다. `materials.json`의 `stuck_moments`는 한 사건이 한 줄이다. `text`가 막힌 순간의 원문(에러, AI의 답이나 정정), `next_user`가 그 뒤 멤버가 보낸 말(재료 3 "방향을 바꾼 한 마디")이다. 후보가 여럿이면 `kind`가 `user_pushback`(멤버가 되돌린 것)인 것부터 쓴다. 멤버가 반응하지 않은 도구 에러는 글감이 아니다. 원문이 잘려 보이면 `materials.json`의 긴 본문을 본다. 모델명은 한글(영문)로 쓴다: "클로드 오푸스 5(Claude Opus 5)". **node가 없거나 제미나이 CLI·오픈코드·안티그래비티 기록이면** `references/devlog-guide.md`대로 직접 읽어 같은 항목을 채운다. 그때 지킬 것: 큐에 쌓인 메시지도 요청이다, 압축 요약("This session is being continued…")은 원문이 아니다, 질문 도구의 자유 입력 답은 그대로 쓴다.

**세션이 없거나, 있는데 못 읽으면**(챗GPT·클로드 웹, 제미나이 앱, 또는 권한 거부로 세션 파일을 못 연 경우) 이렇게 묻는다. 세션을 못 읽었으면 그 사실을 발행메모에 적고, 요청 원문을 커밋이나 문서로 지어 채우지 않는다.

```
이 폴더에서 AI 작업 기록을 못 찾았어요. 둘 중 편한 걸로 주세요.
1. AI와 나눈 대화를 복사해서 붙여 넣기. 길어도 괜찮아요. 처음 보낸 말과 막혔던 부분이 들어가게, 
   내 말과 AI 답이 구분되게 붙여 주세요. (챗GPT 화면을 그대로 복사하면 돼요)
2. 이번에 한 일을 세 줄로 적기
```

붙여 넣은 대화는 `./chat.txt`로 저장하고 `--paste ./chat.txt`로 돌린다. 화자 구분이 안 되면 한 번 다시 부탁한다. 중간에 잘린 답이 보이면 잘린 채로 가고 DEVLOG에 "(여기서 잘림)"만 남긴다. 붙여 넣은 대화에는 날짜·걸린 시간·모델이 없다. ②에서 묻는다. 도구 이름이 대화에 안 보이면 그것도 ②에서 묻는다. **세 줄만 받았으면** DEVLOG 없이 ②로 가고, 요청 원문이 없으니 본문에 요청 코드블록을 넣지 않는다. ②의 9번(기록이 얇을 때)이 항상 붙는다.

**재료 여덟 가지** (`materials.json`의 칸. 없는 칸은 비워 두고 ②에서 묻는다. 지어내지 않는다.)

1. 처음 보낸 요청 원문: 오타·말투 그대로. 가리는 건 넷뿐이다. 사용자 이름 든 절대 경로는 `~/…`로, 로그인해야 열리는 링크는 "(구글포토 링크)"처럼 괄호 설명으로, 키·이메일·전화번호는 지우고, 남의 이름은 역할로.
2. 막힌 순간 원문: 에러 문구, AI의 엉뚱한 답이나 정정("이 영상은 세로가 아니라 가로입니다"), 멤버가 "안 돼", "다시", "이게 뭐야" 한 지점.
3. 방향을 바꾼 한 마디: 막힌 뒤 멤버가 보낸 요청. 없으면(AI가 스스로 풀었으면) 비우고 그렇게 쓴다.
4. 전후 숫자: 세션에서 잰 것과 "전에는 얼마나"(멤버에게 묻는다). 잰 것과 기대치를 구분한다.
5. 시간과 돈: 작업 시간(분 단위 반올림), 로그에 있으면 토큰, 요금제는 묻는다. 비용은 로그에 없으면 안 쓴다.
6. 도구·모델·버전.
7. 결과물 실물: 배포 주소, 저장소, 만든 파일, 그리고 이미지 없이도 읽히는 두 줄 묘사. 결과물이 로그인 뒤에만 보이면 주소 대신 "로그인하면 보이는 것" 두 줄.
8. 아직 안 되는 것: 미룬 것, 세션 끝에 남은 에러.

```
7. 지난 주 글에 이어 쓰면 그 글 주소와 이번이 몇 주차인지. 참고한 공식 문서·강의·멤버 글이 있으면 같이.
   (세션에서 연 자료가 있을 때만) 기록에 이 자료가 있어요: (목록) → 넣을까요?
8. (회사 내부 숫자나 본인 매출·수입이 보일 때만) 매출·고객 수 같은 숫자가 있어요. 어림수로 쓸까요, 뺄까요?
9. (기록이 얇을 때만) 기록이 짧아서 세 가지만 한 줄씩 더 여쭤요.
   왜 이걸 하려고 했어요? / 결과를 어디에 쓰고 누가 봐요? / 아직 안 된 것이나 아쉬운 것 하나?
```

"기록이 얇다"의 기준: `materials.json`의 `user_messages`가 3개 이하이거나, 붙여 넣은 `chat.txt`가 공백 포함 2,000자 미만이거나, 세 줄만 받았을 때. 9번의 셋째 답은 "아직 안 된 것" 절에 넣는다(다음 편 예고로 쓰지 않는다).

- 전부 "알아서 해줘"여도 진행한다. 제목은 ①, 숫자는 세션 값, 입장은 프로필, 기분은 세션에 있는 멤버 말만.
- 비운 숫자는 그 숫자 없이 쓴다. 작업 측정치(시간, 파일 수, "전에는 하루")와 운영 건수(발행 몇 건, 처리 몇 건)는 내부 숫자가 아니니 묻지 않는다. 8번은 매출·고객 수·계약 조건·내부 KPI가 보일 때만. 본인 매출·수입은 `references/rules.md` 3절.
- 멤버 답이 기록과 다르면(전에는 얼마나, 걸린 시간) 멤버 답을 쓴다. 둘 다 늘어놓지 않는다.
- 9번 답은 본문의 사정·결과·아직 안 된 것 절에 그 말 그대로 들어간다. 이걸로도 2,000자가 안 되면 **짧은 글로 낸다**(점검은 [주의]만 낸다). 발행메모에 "기록이 짧아 N자예요. 검색 상위는 어렵고, 다음 과제는 막힌 지점과 결과를 대화에 더 남겨 두면 글이 길어져요"라고 적는다.
- 결과물이 스터디 단톡방·스터디 제공 파일에 기대면 "외부 독자는 못 봐요. 무엇이었는지 한 줄로 적을까요?"를 3번에 붙인다.
- 지난 글 주소는 열어 보지 않는다(웹 접근이 없는 도구도 있다). 멤버가 7번에 적은 주소와 주차를 그대로 쓴다. 주소의 제목 부분이 이번 작업과 무관해 보이면 되묻지 않고, 본문엔 "지난 글: [주소]" 한 줄만 두고 발행메모에 "지난 글이 다른 주제로 보여요. 이어 쓰는 글이 맞는지 봐 주세요"라고 적는다.

**이미지(초안 쓰기 전에).** 캡처가 있으면 열어 보고 가릴 곳을 번호로 제안하고 **답을 기다린다.** 이 한 번은 추가 질문이고, 답이 오면 승인받은 곳만 가린 뒤 초안으로 넘어간다(`references/rules.md` 2절). `python3 <skill>/scripts/blur-region.py 원본.png ./case-post-images/결과.png --blur x,y,w,h`. 스크립트는 Pillow나 ImageMagick 중 하나만 있으면 된다. 둘 다 없으면(종료 코드 2) 가릴 위치를 말로 알려주고 직접 가려 달라고 한다. 좌표가 틀리면(종료 코드 3) 좌표를 고쳐 다시 돌린다. 캡처가 없으면 막지 않는다(185편에서 이미지 수와 검색 성과는 무관했고, 구글 상위권은 5~6장이라 **3장을 목표**로만 둔다). 모든 이미지에 alt 한 줄(숫자나 도구명 포함)과 캡션 한 줄. 이미지 속 숫자는 본문에도 쓴다.

**읽는 순서.** `~/.gpters/write-post/voice.md` → `references/best-cases-185.md` → `references/google-top300.md` → `references/seo-geo-brief.md` 1·2·4·5·7절 → `references/post-templates.md`에서 구성 하나.

**분량.** 본문은 공백 빼고 **2,500자 이상, 3,000~4,000자를 목표**로 쓴다. 구글 상위권 중앙값이 4,100자이고, 지피터스 안에서도 멤버가 쓴 800~1,000자 글은 8~10위, 에디터가 쓴 2,200~5,800자 글은 1~3위였다. 같은 도메인에서 글 모양이 순위를 갈랐다(`references/google-top300.md`). **그러나 분량은 기록으로만 채운다. 기록이 짧으면 짧게 쓴다.** 점검 스크립트는 2,000자·2,500자 미만을 [주의]로만 알린다. 채울 재료는 AI가 한 일의 순서, 설정값·파일·명령 이름, 시도한 순서와 안 된 이유, 결과 화면 묘사, ②의 답이다. 기록에 없는 수치("몇 분 만에"), 기록과 반대되는 요약("처음엔 조건 없이 시켰다"), 출처 추론("○○ 배지가 있는 걸 보니"), 평가·조언·감정으로 채우지 않는다. 검사에서 지어낸 문장 6건이 전부 분량을 채우는 구간에서 나왔다. 7,000자는 넘기지 않는다.

**검색을 위한 자리 (제목과 첫 문단)**

- 제목은 ②에서 고른 것. H1은 이것 하나.
- 첫 문장은 "[도구A]를 [도구B]에 연결해 [결과물]을 만들었어요" 꼴. 영문 표기는 여기서 괄호로: "클로드 코드(Claude Code)".
- 첫 문단은 **120자 안에서 끊는다.** 여기에 숫자 하나, 절대 날짜("2026년 9월 23일에 한 작업", 모르면 "2026년 9월 28일 기준"), 그리고 "○○는 ○○하는 도구예요" 정의 한 줄(새 도구가 아니어도). 같은 뜻의 검색어(크롤링/수집)는 둘째 문단에. 인사·작성자 소개·스터디 안내는 두지 않는다. 첫 문단이 검색 결과 설명문이 되고 발행 후 못 바꾼다.
- 재미있는 한 줄은 첫 문단 둘째 줄부터.

**사람을 위한 본문**

- 작성자의 사정을 끝까지 잇는다. 첫 H2 뒤 `author_line`에서 시작한 사정이 막힌 순간과 결과에서 다시 나온다. 사정·역할·업무 설명은 프로필과 ②의 답에 있는 말만 쓴다. "제가 맡은 일 중 하나가 ○○예요"처럼 기록에 없는 역할을 추론해 쓰지 않는다.
- **형식은 넷.** AI에게 보낸 요청은 코드블록(원문 그대로, 한 블록 8줄까지, 넘으면 보낸 메시지 단위로 나눈다). AI의 답은 인용문(`>`)으로 5줄 이하. 에러·명령 결과는 코드블록 5줄 이하, 길면 "(뒤로 4줄 더)". 맨 끝 따라 할 프롬프트는 코드블록에 [바꿀 부분] 표시.
- **줄이면 줄였다고 쓴다.** 요청 원문을 `...`로 자르지 않는다. 길면 앞 8줄을 넣고 "(뒤로 N줄 더)". 명령·출력에서 경로를 줄이면 "(경로 줄임)"이라고 붙인다. "처음 콘솔에 이렇게 떴다"처럼 원출력으로 보이게 해 놓고 내용을 바꾸지 않는다.
- **시간은 한 숫자.** 작업 시간은 전체 값 하나로 쓴다. "N분 더 했다"는 기록에 두 시점의 값이 따로 있을 때만. 한 세션의 관찰을 "거의 매번", "항상"으로 넓히지 않는다.
- 막힌 순간은 원문 + 바꾼 것 + 결과. **기분 한 줄은 세션의 멤버 말이나 ②의 5번 답에서만.** 둘 다 없으면 사실만. "민망했어요", "자신 있게 넘겼는데"처럼 기록에 없는 감정·태도를 지어 넣지 않는다.
- 결과는 이미지 없이도 읽히게 링크 + 두 줄. 처음 써 본 사람 반응은 결과 절에 그 말 그대로 한 줄.
- "아직 안 된 것"을 쓴다. 앞으로의 계획은 결과보다 짧게, 없으면 안 쓴다.
- 소제목(H2)은 **5~7개**, 그 글의 내용으로 쓰되 **2~3개에는 도구명이나 작업어를 넣는다**("클로드 코드로 시세 지도 만든 순서"). 게시판 기본 틀을 쓰면 "소개: 가계부를 슬랙으로 기록하고 싶었던 이유"처럼 내용을 붙인다.
- 이어 쓰는 글이면 첫 H2 아래 "N주차 과제로, 지난주 [지난 글 제목](주소)에서 만든 ○○에 △△를 붙였어요" 한두 줄. 다음 편 예고·전체 편수는 쓰지 않는다.
- 끝은 따라 할 프롬프트 1개 또는 3~5단계 순서. 프롬프트는 "이렇게 시키면 돼요"로 소개한다. 원문 여러 개를 합쳐 다듬었으면 "제가 보낸 그대로"라고 하지 않는다. 실제로 받은 질문(동료·가족·②의 답)이 있으면 `## 자주 묻는 질문`에 2~3개, 참고한 자료가 있으면 `## 참고한 자료`. 둘 다 없으면 만들지 않는다.

**쓰지 않는 것.** 교훈 격언 맺음("A와 B는 다르다"), 3인칭·AI 시점("사용자가 물었다"), 채움 섹션("다른 업무에 적용한다면?", "이런 분들께 추천"), 근거 없는 숫자와 과장(ROI, "10배", "완전 무인"), 자리표시·안내문("[이미지 1]", "(내용 입력)", 게시판 양식 질문), 줄표, 물결표 범위, 3열 이상 표, 헤지, 남이 못 여는 링크, 사용자 이름 든 경로, 서버 IP.

`./AI_CASE_STUDY.md`로 저장한다. **이 파일에는 게시판에 올릴 본문만 둔다.**

  ```
  2. 처음에 이렇게 시켰다: "(요청 원문)"
  3. 여기서 막혔다: (막힌 순간 한 줄) → 이렇게 바꿨다: "(바꾼 한 마디)"

  4. 결과: (전 → 후 숫자, 결과물 한 줄)
  5. 아직 안 된 것: (한 줄)
  ```

- **"말투 바꿔 줘"**: `references/voice-default.md` 맨 끝 "분위기 문단" 1~4를 번호로 보여주고 고른 문단을 `voice.md` 끝에 붙인다. 프로필 `tone`에 번호를 적는다.
- **"내 글로 문체 뽑아 줘"**: `node <skill>/scripts/fetch-member-posts.mjs "<닉네임>" --limit 30 --out ./my-posts.json`으로 공개 글을 읽고 종결어미 비율·문장 길이·자주 쓰는 표현·도입 방식을 뽑아 `voice.md`를 다시 만든다. 3편 미만이면 기본 문체로.
- **"프로필 다시 설정"**: 처음 1회 설정을 다시.
- playwright·Pillow 설치를 먼저 권하지 않는다. 멤버가 원하면 `npm i -g playwright && npx playwright install chromium`, `pip install pillow`.

## 절대 하지 않는 것

- 검색어를 멤버에게 묻지 않는다. 스킬이 조사해 제목으로 보여준다.
- 숫자·경력·감정을 지어내지 않는다. 기록에 없고 멤버가 비우면 그것 없이 쓴다.
- 남이 못 여는 링크, 사용자 경로, 키, 남의 개인정보를 본문과 이미지에 남기지 않는다(`references/rules.md` 1~3절).
- 틀 소제목을 쓰지 않는다. 한 주 수백 편이 같은 뼈대가 되면 사이트 전체가 손해를 본다.
- 요청 원문을 다듬지 않는다. 오타와 말투가 사람이 쓴 표시다.
- 본문 파일에 메모·자리표시·안내문을 넣지 않는다. 그런 건 발행메모로.
- 무언가를 설치하라고 먼저 권하지 않는다. 없으면 대체한다.
- 발행하지 않는다. 발행메모까지가 이 스킬의 끝이다.
