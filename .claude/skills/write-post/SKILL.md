# 지피터스 사례 게시글 (검색·AI 인용 구조)

이번에 AI로 한 일을, 검색과 AI 답변 엔진이 찾아 인용할 수 있는 지피터스 글로 만든다. 멤버가 하는 일은 세 가지뿐이다. **제목 하나 고르기, 숫자 확인하기, 캡처 찍어 오기.** 나머지는 스킬이 세션과 프로필에서 뽑아 확인만 받는다.

스터디 기간에는 이 스킬로 한 주 수백 편이 올라온다. 그래서 두 가지를 특히 지킨다. **제목이 서로 겹치지 않게** 구체적인 대상·업무를 넣고, **틀로 찍은 글처럼 보이지 않게** 소제목을 글 내용으로 쓴다(`references/seo-geo-brief.md` 7절).

```
처음 1회 설정 → Phase 1 DEVLOG → Phase 2 DEVLOG 확인 → Phase 3 글(뽑기 → 제목 → 질문 → 이미지 → 초안 → 게이트 → 마무리)
```

각 Phase를 시작할 때 현재 위치를 한 줄로 알린다. 예: `지금 여기: Phase 3 / 3, 제목 고르기`

**질문은 텍스트 번호 목록으로 묻는다.** 질문 도구는 보기 4개 제한이 있고 코덱스 등에는 그 도구가 없다. 모든 환경에서 같은 방식으로 묻는다.

**Phase 3의 단계는 todo·task 목록에 올리지 않는다.** 매 단계 멤버 답이 필요해서 자동 진행 훅이 반복 발동한다.

## 처음 1회 설정 (프로필이 없을 때만)

`~/.gpters/write-post/profile.json`과 `voice.md`가 있으면 이 절을 건너뛴다. "프로필 다시 설정"이라고 하면 다시 연다.

**질문 1.** "지피터스 닉네임이 무엇이세요? 프로필에 보이는 이름 그대로요."

**질문 2.** "지금 참여 중인 기수와 스터디를 알려 주세요. 게시판 태그에 보이는 그대로요. 예: 24기 GEO실험실 (스터디가 아니면 '없음')"

**질문 3.** 아래를 그대로 보여준다.

```
이번 글들을 어떤 입장에서 쓰세요? 가까운 번호를 고르고 한 줄 덧붙여 주세요.
회사나 가게 이름은 안 적어도 돼요.

1. 회사에서 일해요            (예: 제조업 회사 구매 담당 7년 차)
2. 내 가게·사업을 해요         (예: 동네 반찬가게 운영, 온라인 쇼핑몰 1인 운영)
3. 창업했거나 준비 중이에요     (예: 교육 앱 창업 2년 차)
4. 프리랜서·강사·크리에이터예요 (예: 유튜브 요리 채널 운영)
5. 쉬면서 다음을 준비 중이에요   (예: 퇴사하고 AI로 전직 준비 중)
6. 학생·주부·기타             (예: 두 아이 키우며 AI 공부 중)

AI는 얼마나 써 보셨어요? (처음 / 몇 달 / 1년 넘게)
```

직함이 아니라 **입장**을 받는다. 작성자 신호로는 "이 사람이 이 문제를 직접 겪었나"가 가장 세다(`references/seo-geo-brief.md` 4절). 5번, 6번도 똑같이 좋은 신호다. "AI 처음 써 본 사람이 해냈다"는 그 자체로 독자가 찾는 글이다. 회사명·가게 이름·실명을 적으면 "글에는 '동네 반찬가게'처럼 쓸까요?"로 일반 명사를 제안한다.

**질문 4.**

```
글쓰기 추구미가 있으신가요?
1. 짧고 간결하게: 결론이 첫 줄에 오고, 문단은 세 줄을 넘지 않아요.
2. 친절하고 재밌게: 어요체로 말 걸듯 쓰고, "저도 여기서 한 번 망했어요" 같은 솔직한 한 줄이 들어가요.
3. 시크하고 프로페셔널하게: 습니다체, 이모지와 감탄사 없이 사실과 결과만.
4. 신뢰도 있고 진중하게: 숫자마다 출처와 확인일을 붙이고, 확실하지 않은 건 확실하지 않다고 써요.
5. 잘 모르겠어요.
```

**그다음은 스킬이 한다.**

1. 닉네임으로 공개 글을 가져온다. 토큰·로그인 필요 없음. node가 필요하다.
   ```bash
   node <skill>/scripts/fetch-member-posts.mjs "<닉네임>" --limit 30 --out ./my-posts.json
   ```
   찾지 못하면 한 번 더 묻고, 그래도 안 되거나 node가 없으면 "예전에 쓴 글 주소 세 개만 붙여 주세요"로 받는다. 없다고 하면 넘어간다.
2. 글이 **3편 이상**이면 읽어서 뽑는다: 종결어미 비율(어요/니다), 문장 길이 리듬, 자주 쓰는 표현 5개, 도입 방식(장면/결론/질문), 이모지·소제목 습관, 글 구성(이야기형·매뉴얼형·리뷰형). 3편 미만이면 `references/voice-default.md`로 가고, 나중에 "문체 다시 뽑기"를 안내한다.
3. 추구미 1~4면: 고른 말투 + 글에서 뽑은 구성·습관으로 `voice.md` 초안을 만들어 **"이렇게 만들었어요, 이대로 갈까요?"** 한 번만 확인한다. 추구미 5면: 뽑은 문체를 보여주고 **"이런 걸 선호하시는 게 맞을까요?"**로 확인한다.
4. 작성자 한 줄을 만들어 **"글에 이렇게 표기할게요"**로 확인만 받는다. 예: "지피터스 24기 GEO실험실 멤버 반찬엄마예요. 동네에서 반찬가게를 하면서 AI를 석 달째 써 보고 있어요."
5. 저장한다. `voice.md`에는 `references/voice-default.md`의 "쓰지 않는다" 절을 항상 넣는다.

```json
// ~/.gpters/write-post/profile.json
{ "nickname": "반찬엄마", "cohort_tag": "24기 GEO실험실", "stance": "2", "stance_line": "동네에서 반찬가게를 하고 있어요", "ai_experience": "몇 달", "author_line": "지피터스 24기 GEO실험실 멤버 반찬엄마예요. 동네에서 반찬가게를 하면서 AI를 석 달째 써 보고 있어요.", "tone": "2", "set_at": "2026-09-23" }
```

## 매번: 시작 전 확인

오늘 날짜를 명령으로 확인한다. 날짜는 추정하지 않는다. 본문 날짜와 확인일에 쓴다. 이어서 아래가 있는지 본다. Windows면 `python3` 대신 `python`, 셸 문법은 그 환경에 맞춘다.

- 프로필(`~/.gpters/write-post/profile.json`): 없으면 처음 1회 설정.
- python: 없으면 게이트를 스크립트 대신 `references/rules.md` 4절 체크리스트로 직접 검사한다.
- node + playwright: 없으면 카드·폰 미리보기를 건너뛴다. 설치를 권하지 않는다. 멤버가 먼저 원하면 `npm i -g playwright && npx playwright install chromium`을 알려준다.
- 웹 검색 도구: 없으면 검색 조사를 건너뛰고 제목 공식만 쓴다.

빠진 것이 있어도 멈추지 않는다. 대체하고 마무리 때 무엇을 건너뛰었는지 알린다.

이번 글의 입장이 프로필과 다를 수 있다. 3-3 질문에서 한 줄로 확인한다.

## Phase 1: DEVLOG 생성

> 지금 여기: Phase 1 / 3, DEVLOG 생성

사용 가능한 AI 코딩 도구의 세션을 현재 프로젝트 기준으로 스캔해 `DEVLOG.md`를 만든다. **세션 스캔·파싱·출력 포맷·기존 DEVLOG 이어 쓰기의 세부는 `references/devlog-guide.md`를 그대로 따른다.** 여기서는 추가로 하는 것만 적는다.

**추가 1. 숫자를 세션에서 뽑아 둔다.** 글의 근거가 된다.

- 작업 소요 시간: 첫 메시지와 마지막 메시지의 타임스탬프 차이. 세션이 여러 개면 합산, 30분 넘게 쉰 구간은 뺀다.
- 만들거나 고친 파일 수, 커밋 수(git을 쓸 때만)
- 에러가 난 횟수와 다시 시도한 횟수
- 처리 건수: 반복 작업이면 변환한 파일 수, 만든 문구 수 같은 것
- 토큰·비용: 세션 로그에 있을 때만

DEVLOG 끝에 `## 숫자 후보` 절로 적는다. 숫자를 지어내지 않는다.

**추가 2. 막힌 지점을 표시해 둔다.** 에러가 난 뒤 접근을 바꾼 지점, 멤버가 "안 돼", "다시" 같은 말을 한 지점을 `## 막힌 지점 후보`로 2~3개 적는다. 글에서 "사람이 쓴 표시"가 된다.

**세션이 없으면** (챗GPT·클로드 웹, 제미나이 앱에서 한 작업 등) 이렇게 묻는다.

```
이 폴더에서 AI 작업 기록을 못 찾았어요. 둘 중 편한 걸로 주세요.
1. AI와 나눈 대화를 복사해서 붙여 넣기 (길어도 괜찮아요)
2. 이번에 한 일을 세 줄로 적기
```

붙여 넣은 대화도 같은 포맷으로 DEVLOG를 만든다. 세 줄만 받았으면 DEVLOG를 건너뛰고 Phase 3로 가서, 숫자는 3-3 질문 4에서 받는다.

## Phase 3: 글 작성

> 지금 여기: Phase 3 / 3, 글 작성

### 3-1. 스킬이 먼저 뽑는다 (묻기 전에)

DEVLOG에서 아래를 뽑아 둔다. 이게 질문의 보기가 된다.

- **도구·기능 이름 2~3개**(한글·영문 같이): 질문 1의 보기이자 검색어 재료.
- **한 일 한 줄 2~3개**: 질문 2의 보기. **무엇을 대상으로** 했는지가 들어가게 한다. "엑셀 정리" 말고 "세금계산서 한 달 치 엑셀 정리".
- **숫자 후보**: 질문 4.
- **막힌 지점 1개**: 확인만 받는다.
- **찍을 장면 3개**: ① 결과 화면 ② 전후 비교 ③ 막혔던 순간(에러 메시지나 바꾼 설정). 장면마다 "어디를 열어서 뭐가 보이게"를 한 줄로.

### 3-2. 검색어 조사 → 제목 3개

**멤버에게 검색어를 묻지 않는다.** `references/seo-geo-brief.md` 6절 순서로 스킬이 조사한다.

**제목 공식: 도구명(한영) + 구체적 대상·업무 + 의도 + 결과 숫자.** 50자 이내, 줄표 대신 콜론.

- 대상·업무는 3-1의 "한 일"과 프로필의 입장에서 가져온다. 이게 수백 편 사이에서 이 글을 가른다.
- `site:gpters.org 도구명 업무`로 같은 도구 + 같은 업무 글이 있는지 본다. 있으면 의도(설정·비교·가격·후기)나 대상(업종·규모)을 튼다.
- 제목에 넣지 않는 것: "[24기 ○○]" 같은 기수 머리말, "[2주차 과제]" 같은 주차 표기, 시리즈 번호, 나만 아는 별명. 기수·스터디는 태그가, 주차는 본문 첫 소제목 아래가 맡는다.

```
❌ 클로드 코드 사용법: 업무 자동화 후기
❌ 드디어 해냈다! 나만의 첫 자동화 도전기
⭕ 클로드 코드(Claude Code)로 세금계산서 엑셀 정리: 40분에서 3분으로
⭕ 챗GPT로 반찬가게 인스타 문구 한 달 치 만들기: 30개를 2시간에
```

수요가 안 잡히면 그 자리에서 말한다. "이 주제는 검색이 거의 없어요. 쓴 도구 이름을 앞세우면 이렇게 됩니다"라고 대안 제목을 내고, 그래도 없으면 **기록형**으로 표시하고 넘어간다(`references/rules.md` 6절).

### 3-3. 질문 (한 번에 보여주고, 보기는 스킬이 채움)

DEVLOG에 답이 분명한 항목은 묻지 않고 "이렇게 쓸게요"로 확인만 받는다.

```
1. 쓴 도구나 기능 이름이 뭐예요?                 → 보기: (도구명 2~3개)
2. 그걸로 뭘 했어요? 한 줄로요.                  → 보기: (한 일 2~3개)
3. 이 중 어떤 제목이 제일 가까워요?               → 보기: (제목 3개) + 직접 쓰기
4. 이 숫자들 맞아요? 빠진 게 있으면 적어 주세요.   → (숫자 목록) + "AI 쓰기 전에는 얼마나 걸렸어요?"
5. 이 세 장면을 찍어서 파일 경로만 알려 주세요.    → (장면 3개) + "이 장면은 못 찍어요" 가능
   폴더 경로·이메일·키 같은 건 제가 가려 드려요.
6. 이번 글도 "(프로필 입장 한 줄)" 입장으로 쓸까요? → 다르면 한 줄로
7. 지난 주에 이어 쓰는 글이면 그 글 주소를, 참고한 자료(공식 문서, 강의, 멤버 글, 도움 준 분)가 있으면 알려 주세요. → 없으면 "없음"
```

- 전부 "알아서 해줘"여도 진행한다. 제목은 1번 후보, 숫자는 세션 값, 입장은 프로필, 캡처는 카드나 "찍으면 좋을 장면" 목록으로 대체.
- 질문 4의 "전에는 얼마나"만 세션에 없는 숫자다. 비우면 전후 비교 없이 쓴다. 지어내지 않는다.
- 숫자 중 공개 여부를 본인이 정할 것(매출, 수입, 회사 내부 수치)은 `references/rules.md` 3절대로 한 번 묻는다.
- 질문 7의 지난 글은 `fetch-member-posts.mjs`로 가져온 목록에 있으면 제목을 보여주며 "이 글에 이어지는 거죠?"로 확인만 받는다. 주차 과제는 대개 같은 프로젝트를 주마다 이어 쓴다.

### 3-4. 이미지

목표는 글 1편에 이미지 3장 이상, 그중 실제 화면 캡처 1장 이상이다. 못 채워도 발행은 막지 않는다. 작업 폴더는 `./case-post-images/`.

**① 실제 캡처 + 가리기 (늘 한다)**

멤버가 준 캡처를 열어 본다. 가릴 후보를 찾아 번호로 묻는다. "① 왼쪽 위 폴더 경로 ② 오른쪽 거래처 이름, 이 두 곳 가릴까요?" 승인받은 곳만 가린다.

```bash
python3 <skill>/scripts/blur-region.py 원본.png ./case-post-images/결과.png --blur x,y,w,h [--blur ...] [--crop-top N]
```

가리는 것과 가리지 않는 것은 `references/rules.md` 2절. 가린 결과를 다시 열어 "이렇게 가렸어요"로 보여준다. Pillow·ImageMagick이 없으면 가릴 위치를 말로 알려주고 직접 가려 달라고 한다.

**② 숫자 비교·흐름 카드 (playwright가 있을 때만)**

전후 숫자가 분명하면 카드 1장을 만든다. `references/tpl-compare.html`(숫자 두 개 비교)이나 `references/tpl-two-roles.html`(둘로 나누기)을 복사해 숫자와 한 줄 문구만 바꾼다.

```bash
mkdir -p ./case-post-images && cp <skill>/references/_diagram.css ./case-post-images/
# ./case-post-images/card-1.html 작성 (.stage 안에 도식)
node <skill>/scripts/capture-card.mjs ./case-post-images/card-1.html   # → card-1.png (여백 제거, @2x)
```

- 세로 한 열, 폭 520~560px, 글자 28px 이상, 한 장에 생각 하나(30자 이내, 5줄 이내).
- 도구가 낯선 독자용 개념 도식이 필요하면 `references/eli5-template.html`을 복사해 제목·상자·설명 세 줄만 바꾼다.
- 만든 PNG는 열어서 글자 깨짐·줄바꿈을 눈으로 본다.

playwright가 없으면 카드는 건너뛰고, 못 찍은 장면은 마무리 때 "찍으면 좋을 장면" 목록으로 남긴다.

**alt는 모든 이미지에 쓴다.** 숫자나 도구명이 들어간 한 줄. "스크린샷"이라고만 쓰지 않는다. 카드와 캡처에 있는 숫자는 본문 문장에도 한 번 더 쓴다. 크롤러와 AI는 이미지 속 글자를 읽지 못한다고 가정한다.

### 3-5. 초안 작성

읽는 순서: `~/.gpters/write-post/voice.md`(없으면 `references/voice-default.md`) → `references/seo-geo-brief.md` 1·2·4·5·7절 → `references/post-templates.md`에서 구성 하나.

구성은 글 내용에 맞춰 고른다. 늘 같은 구성을 쓰지 않는다. 어느 구성이든 아래는 고정이다.

- **제목**: 3-3에서 고른 것. H1은 이것 하나뿐.
- **첫 150자**: 정의문 또는 답 + 숫자 하나 + 도구명 한글(영문). 본문 안에 "2026년 9월 23일 기준"처럼 절대 날짜를 한 번 이상. 요금·버전처럼 바뀌는 정보가 있으면 여기에. 인사말, 작성자 소개, 스터디·행사 안내는 여기 두지 않는다. 이 구간이 검색 결과 설명문이 되고 발행 후 못 바꾼다.
- **소제목(H2)**: 그 글의 내용으로 쓴다. 독자가 검색할 질문이나 그 섹션의 결론. "한줄 요약", "이런 분들께 도움돼요", "문제 상황", "작업 과정" 같은 틀 이름만 달랑 쓰지 않는다.
  - 게시판 기본 틀(소개 / 진행 방법 / 결과와 배운 점)은 필수가 아니다. 멤버가 원하거나 프로필에서 그 틀을 쓰던 습관이 보이면 순서는 따르되 **틀 이름 뒤에 내용을 붙인다.** "소개: 가계부를 슬랙으로 자동 기록하고 싶었던 이유", "결과와 배운 점: 7단계가 3단계로 줄었다".
- **이어 쓰는 글이면**: 첫 H2 아래 한두 줄로 "N주차 과제로, 지난주 [지난 글 제목](주소)에서 만든 ○○에 △△를 붙였어요"라고 쓰고, 이번 주에 달라진 것부터 쓴다. 지난 글 내용을 다시 풀지 않는다. 다음 주 예고, 앞으로 쓸 편 목록, 총 몇 편인지는 쓰지 않는다.
- **작성자 신호**: 첫 H2 뒤 또는 글 하단에 프로필의 `author_line`. 이 글과의 관련성을 한 마디 붙인다("이 숫자는 제 가게 한 달 치로 직접 잰 거예요").
- **본문**: 숫자마다 출처 또는 "제가 잰 것". 막힌 지점 1개는 반드시. AI에게 보낸 요청은 코드블록, 독자용 프롬프트는 인용문. 소스코드는 넣지 않는다.
- **끝**: 따라 할 프롬프트 1개 또는 3~5단계 순서.
- **참고한 자료**(있을 때만): 맨 끝에 `## 참고한 자료` 목록. 항목마다 무엇을 가져왔는지 한 줄. "[노션 API 공식 문서](주소): 데이터베이스 속성 이름 규칙", "2주차 강의(○○님): 실패 사례도 공유하라는 조언". 공식 문서 링크는 AI가 보는 출처 신호가 된다. 없으면 섹션을 만들지 않고, "별도 참고 없음" 같은 문장도 쓰지 않는다.
- **금지**: 줄표, 물결표 범위, 3열 이상 표, 첫째·둘째, 헤지, 남이 못 여는 링크, 사용자 이름 든 경로.

`./AI_CASE_STUDY.md`로 저장한다. 게시판에 그대로 붙여 넣을 파일이라 frontmatter는 넣지 않는다.

### 3-6. 게이트

python이 있으면:

```bash
python3 <skill>/scripts/check-gate.py ./AI_CASE_STUDY.md --keyword "<도구명 한글>" --keyword-en "<영문>" --author "<닉네임>"
python3 <skill>/scripts/check-ai-tell.py ./AI_CASE_STUDY.md
```

`[막힘]`이 0개가 될 때까지 고치고 다시 돌린다. `[주의]`는 멤버에게 알리기만 한다. python이 없으면 `references/rules.md` 4절·4-1절을 한 줄씩 직접 대조하고 "자동 검사 대신 직접 확인했어요"라고 말한다.

playwright가 있으면 폰 화면으로도 찍어 본다.

```bash
node <skill>/scripts/preview-mobile.mjs ./AI_CASE_STUDY.md --width 390
```

한 문단이 화면 절반을 넘는 곳, 글만 세 화면 넘게 이어지는 곳이 있으면 문단을 쪼개거나 이미지를 옮긴다.

그다음 사람이 보는 다섯 가지를 보여주고 확인받는다.

```
[ ] 제목이 약속한 질문에 본문이 실제로 답하나요
[ ] 숫자마다 출처 또는 "제가 잰 것"이 붙었나요
[ ] 막힌 지점 하나가 들어갔나요
[ ] 따라 할 프롬프트나 순서가 있나요
[ ] 이미지 속에 경로·이메일·키·남의 이름이 안 보이나요 (이미지 목록을 같이 보여준다)
```

### 3-7. 마무리

- 초안 첫 150자를 보여주며 "이 부분이 검색 결과 설명문이 돼요. 발행 후엔 못 바꿔요"라고 알린다.
- **태그**: 프로필의 `cohort_tag`(예: `24기 GEO실험실`)는 필수. 이미 게시판에 만들어져 있으니 새로 만들지 말고 목록에서 고르라고 안내한다. 여기에 도구명 태그를 한글·영문으로 2~4개 추천한다(예: `클로드 코드`, `Claude Code`). 새 태그를 만들기 전에 게시판 태그 검색에서 같은 표기가 있는지 먼저 보라고 한다.
- **게시판**: 스터디 안내에 정해진 게시판이 있으면 그곳. 없으면 글 주제에 맞는 게시판.
- 이미지 파일 목록과 각 alt, 들어갈 위치(어느 소제목 아래)를 보여준다. 못 찍은 장면이 있으면 "찍으면 좋을 장면" 목록도.
- 건너뛴 것(검색 조사, 자동 게이트, 카드)이 있으면 한 줄로 알린다.
- 올리는 방법을 안내한다. 발행은 멤버가 한다.

```
게시판에 올리는 방법
1. AI_CASE_STUDY.md 파일에서 마우스 우클릭 → "미리보기 열기" (또는 Cmd+Shift+V, 윈도우는 Ctrl+Shift+V)
2. 미리보기 화면에서 Cmd+A(Ctrl+A)로 전체 선택 → 복사
3. 지피터스 글쓰기 화면에 붙여넣기
4. 안내된 위치에 이미지 넣고, alt(대체 텍스트) 칸에 알려드린 문장 넣기
5. 태그 달고 게시
```

- "다음 글은 같은 명령으로 시작하면 처음 설정 없이 바로 Phase 1로 가요"로 끝낸다.

## 절대 하지 않는 것

- 검색어를 멤버에게 묻지 않는다. 스킬이 조사해 제목으로 보여준다.
- 숫자를 지어내지 않는다. 세션에 없고 멤버가 비우면 그 숫자 없이 쓴다.
- 없는 경력이나 입장을 지어내지 않는다. 회사명·가게 이름·실명은 본인이 원할 때만.
- 남이 못 여는 링크, 사용자 경로, 키, 남의 개인정보를 본문과 이미지에 남기지 않는다(`references/rules.md` 1~3절).
- 틀 소제목을 쓰지 않는다. 한 주 수백 편이 같은 뼈대가 되면 사이트 전체가 손해를 본다.
- 무언가를 설치하라고 먼저 권하지 않는다. 없으면 대체한다.
- 발행하지 않는다. 마무리 안내까지가 이 스킬의 끝이다.
