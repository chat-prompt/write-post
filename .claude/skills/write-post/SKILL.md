# 지피터스 사례 게시글 (검색·AI 인용 구조)

이번에 AI로 한 일을, 검색과 AI 답변 엔진이 찾아 인용할 수 있는 지피터스 글로 만든다. 멤버가 하는 일은 세 가지뿐이다. **제목 하나 고르기, 숫자 확인하기, 캡처 찍어 오기.** 나머지는 스킬이 세션과 프로필에서 뽑아 확인만 받는다.

스터디 기간에는 이 스킬로 한 주 수백 편이 올라온다. 그래서 두 가지를 특히 지킨다. **제목이 서로 겹치지 않게** 구체적인 대상·업무를 넣고, **틀로 찍은 글처럼 보이지 않게** 소제목을 글 내용으로 쓴다(`references/seo-geo-brief.md` 7절).

```
처음 1회 설정 → Phase 1 DEVLOG → Phase 2 DEVLOG 확인 → Phase 3 글(뽑기 → 제목 → 질문 → 이미지 → 초안 → 게이트 → 마무리)
```

각 Phase를 시작할 때 현재 위치를 한 줄로 알린다. 예: `지금 여기: Phase 3 / 3, 제목 고르기`

**질문은 텍스트 번호 목록으로 묻는다.** 질문 도구는 보기 4개 제한이 있고 코덱스 등에는 그 도구가 없다. 모든 환경에서 같은 방식으로 묻는다.

**Phase 3의 단계는 todo·task 목록에 올리지 않는다.** 매 단계 멤버 답이 필요해서 자동 진행 훅이 반복 발동한다.

## 처음 1회 설정 (프로필이 없을 때만)

`~/.gpters/write-post/profile.json`과 `voice.md`가 있으면 이 절을 건너뛴다. "프로필 다시 설정"이라고 하면 다시 연다.

**질문 1.** "지피터스 닉네임이 무엇이세요? 프로필에 보이는 이름 그대로요."

**질문 2.** "지금 참여 중인 기수와 스터디를 알려 주세요. 게시판 태그에 보이는 그대로요. 예: 24기 GEO실험실 (스터디가 아니면 '없음')"

**질문 3.** 아래를 그대로 보여준다.

```
이번 글들을 어떤 입장에서 쓰세요? 가까운 번호를 고르고 한 줄 덧붙여 주세요.
회사나 가게 이름은 안 적어도 돼요.

1. 회사에서 일해요            (예: 제조업 회사 구매 담당 7년 차)
2. 내 가게·사업을 해요         (예: 동네 반찬가게 운영, 온라인 쇼핑몰 1인 운영)
3. 창업했거나 준비 중이에요     (예: 교육 앱 창업 2년 차)
4. 프리랜서·강사·크리에이터예요 (예: 유튜브 요리 채널 운영)
5. 쉬면서 다음을 준비 중이에요   (예: 퇴사하고 AI로 전직 준비 중)
6. 학생·주부·기타             (예: 두 아이 키우며 AI 공부 중)

AI는 얼마나 써 보셨어요? (처음 / 몇 달 / 1년 넘게)
```

직함이 아니라 **입장**을 받는다. 작성자 신호로는 "이 사람이 이 문제를 직접 겪었나"가 가장 세다(`references/seo-geo-brief.md` 4절). 5번, 6번도 똑같이 좋은 신호다. "AI 처음 써 본 사람이 해냈다"는 그 자체로 독자가 찾는 글이다. 회사명·가게 이름·실명을 적으면 "글에는 '동네 반찬가게'처럼 쓸까요?"로 일반 명사를 제안한다.

**질문 4.**

```
글쓰기 추구미가 있으신가요?
1. 짧고 간결하게: 결론이 첫 줄에 오고, 문단은 세 줄을 넘지 않아요.
2. 친절하고 재밌게: 어요체로 말 걸듯 쓰고, "저도 여기서 한 번 망했어요" 같은 솔직한 한 줄이 들어가요.
3. 시크하고 프로페셔널하게: 습니다체, 이모지와 감탄사 없이 사실과 결과만.
4. 신뢰도 있고 진중하게: 숫자마다 출처와 확인일을 붙이고, 확실하지 않은 건 확실하지 않다고 써요.
5. 잘 모르겠어요.
```

**그다음은 스킬이 한다.**

1. 닉네임으로 공개 글을 가져온다. 토큰·로그인 필요 없음. node가 필요하다.
   ```bash
   node <skill>/scripts/fetch-member-posts.mjs "<닉네임>" --limit 30 --out ./my-posts.json
   ```
   찾지 못하면 한 번 더 묻고, 그래도 안 되거나 node가 없으면 "예전에 쓴 글 주소 세 개만 붙여 주세요"로 받는다. 없다고 하면 넘어간다.
2. 글이 **3편 이상**이면 읽어서 뽑는다: 종결어미 비율(어요/니다), 문장 길이 리듬, 자주 쓰는 표현 5개, 도입 방식(장면/결론/질문), 이모지·소제목 습관, 글 구성(이야기형·매뉴얼형·리뷰형). 3편 미만이면 `references/voice-default.md`로 가고, 나중에 "문체 다시 뽑기"를 안내한다.
3. 추구미 1~4면: 고른 말투 + 글에서 뽑은 구성·습관으로 `voice.md` 초안을 만들어 **"이렇게 만들었어요, 이대로 갈까요?"** 한 번만 확인한다. 추구미 5면: 뽑은 문체를 보여주고 **"이런 걸 선호하시는 게 맞을까요?"**로 확인한다.
4. 작성자 한 줄을 만들어 **"글에 이렇게 표기할게요"**로 확인만 받는다. 예: "지피터스 24기 GEO실험실 멤버 반찬엄마예요. 동네에서 반찬가게를 하면서 AI를 석 달째 써 보고 있어요."
5. 저장한다. `voice.md`에는 `references/voice-default.md`의 "쓰지 않는다" 절을 항상 넣는다.

```json
// ~/.gpters/write-post/profile.json
{ "nickname": "반찬엄마", "cohort_tag": "24기 GEO실험실", "stance": "2", "stance_line": "동네에서 반찬가게를 하고 있어요", "ai_experience": "몇 달", "author_line": "지피터스 24기 GEO실험실 멤버 반찬엄마예요. 동네에서 반찬가게를 하면서 AI를 석 달째 써 보고 있어요.", "tone": "2", "set_at": "2026-09-23" }
```

## 매번: 시작 전 확인

오늘 날짜를 명령으로 확인한다. 날짜는 추정하지 않는다. 본문 날짜와 확인일에 쓴다. 이어서 아래가 있는지 본다. Windows면 `python3` 대신 `python`, 셸 문법은 그 환경에 맞춘다.

- 프로필(`~/.gpters/write-post/profile.json`): 없으면 처음 1회 설정.
- python: 없으면 게이트를 스크립트 대신 `references/rules.md` 4절 체크리스트로 직접 검사한다.
- node + playwright: 없으면 카드·폰 미리보기를 건너뛴다. 설치를 권하지 않는다. 멤버가 먼저 원하면 `npm i -g playwright && npx playwright install chromium`을 알려준다.
- 웹 검색 도구: 없으면 검색 조사를 건너뛰고 제목 공식만 쓴다.

빠진 것이 있어도 멈추지 않는다. 대체하고 마무리 때 무엇을 건너뛰었는지 알린다.

이번 글의 입장이 프로필과 다를 수 있다. 3-3 질문에서 한 줄로 확인한다.

## Phase 1: DEVLOG 생성

> 지금 여기: Phase 1 / 3, DEVLOG 생성

사용 가능한 AI 코딩 도구의 세션을 현재 프로젝트 기준으로 스캔해 `DEVLOG.md`를 만든다. **세션 스캔·파싱·출력 포맷·기존 DEVLOG 이어 쓰기의 세부는 `references/devlog-guide.md`를 그대로 따른다.** 여기서는 추가로 하는 것만 적는다.

**추가. 글의 재료를 세션에서 뽑아 둔다.** 베스트 사례에서 과정과 결과를 제대로 담은 글에는 늘 있었고 약한 글에는 빠져 있던 것들이다(`references/best-cases-185.md` 2절). DEVLOG 끝에 `## 재료 후보` 절로 적는다.

- 처음 보낸 요청 원문(말투·오타 그대로), 막힌 순간의 에러·AI 답 원문, 그 뒤 방향을 바꾼 요청 원문
- 걸린 시간(첫 메시지부터 마지막 메시지까지, 30분 넘게 쉰 구간은 뺀다), 만들거나 고친 파일 수, 재시도 횟수, 처리 건수
- 로그에 있으면 모델명·토큰·비용, 설치한 도구·버전
- 결과물 흔적: 배포 주소, 저장소 주소, 만든 파일 이름
- 세션 끝에 남은 에러, 멤버가 "나중에", "일단 빼자"라고 한 것

숫자와 원문을 지어내지 않는다. 못 찾은 칸은 비워 둔다.

**세션이 없으면** (챗GPT·클로드 웹, 제미나이 앱에서 한 작업 등) 이렇게 묻는다.

```
이 폴더에서 AI 작업 기록을 못 찾았어요. 둘 중 편한 걸로 주세요.
1. AI와 나눈 대화를 복사해서 붙여 넣기 (길어도 괜찮아요)
2. 이번에 한 일을 세 줄로 적기
```

붙여 넣은 대화도 같은 포맷으로 DEVLOG를 만든다. 세 줄만 받았으면 DEVLOG를 건너뛰고 Phase 3로 가서, 재료표의 빈 칸을 3-3에서 받는다. 대화를 붙여 넣을 때 "처음 보낸 말과 막혔던 부분이 들어가게 붙여 주세요"라고 한 줄 덧붙인다.

## Phase 3: 글 작성

> 지금 여기: Phase 3 / 3, 글 작성

이 Phase를 시작하기 전에 `references/best-cases-185.md`를 읽는다. 베스트 사례 185편에서 나온 근거가 여기 있다. 이 Phase의 목표는 세 가지다.

1. **사람이 쓴 글로 읽힌다.** 작성자의 사정, 다듬지 않은 요청, 막힌 순간의 감정, 아직 안 된 것.
2. **과정과 결과가 담긴다.** 재료 여덟 가지(3-1)가 빠짐없이.
3. **검색에 걸린다.** 검색은 제목과 첫 문단이 맡고, 본문은 사람을 위해 쓴다.

### 3-1. 재료 여덟 가지를 먼저 채운다 (묻기 전에)

DEVLOG와 세션에서 아래를 뽑아 `재료표`를 만든다. **세션에서 찾은 건 확인만 받고, 빈 칸만 묻는다.**

1. **처음 보낸 요청 원문**: 세션의 첫 의미 있는 사용자 메시지. 오타·말투 그대로. 개인정보만 가린다.
2. **막힌 순간 원문**: 에러 문구, AI의 엉뚱한 답, 멤버가 "안 돼", "다시", "이게 뭐야" 한 지점과 그 직전 출력.
3. **방향을 바꾼 한 마디**: 막힌 뒤 멤버가 보낸 요청 중 결과를 바꾼 것. 무엇을 무엇으로 바꿨는지.
4. **전후 숫자**: 세션에서 잰 것(시간, 건수, 파일 수, 재시도 횟수)과 멤버에게 물어야 할 것(전에는 얼마나). 잰 것과 기대치를 구분해 표시한다.
5. **시간과 돈**: 세션 시작부터 끝까지 걸린 시간, 로그에 있으면 토큰·비용, 쓴 요금제.
6. **도구·모델 이름과 버전**: 세션 메타데이터·로그에 있는 모델명, 설치한 패키지·앱 버전.
7. **결과물 실물**: 배포 주소, GitHub, 만든 파일 이름, 결과 화면. 그리고 이미지 없이 결과를 설명하는 한두 줄.
8. **아직 안 되는 것**: 멤버가 포기하거나 미룬 것, 세션 끝에 남은 에러.

추가로 뽑아 두는 것: 도구명 2~3개(한글·영문), 한 일 한 줄 2~3개(무엇을 대상으로 했는지 들어가게), 찍을 장면 3개(① 결과 화면 ② 전후 비교 ③ 막혔던 순간, 장면마다 "어디를 열어서 뭐가 보이게" 한 줄).

### 3-2. 제목 3개

**멤버에게 검색어를 묻지 않는다.** `references/seo-geo-brief.md` 6절 순서로 스킬이 조사하고, `references/best-cases-185.md` 3절 규칙으로 제목을 만든다.

**제목 공식: [도구A 한글](+ [도구B]) + [사람들이 치는 작업 명사] + [무엇을 대상으로].** 도구명은 앞 15~20자 안에. 50자 이내, 줄표 대신 콜론.

- 작업 명사: 연동, 만들기, 자동화, 크롤링, 사용법, 설정, 비교. 대상이 대중적이면(네이버 부동산, 스마트스토어, 엑셀) 그 말을 제목에 그대로.
- 도구를 둘 이상 썼으면 둘 다 넣는다. 185편에서 가장 강한 신호였다(클릭 중앙값 47 대 6).
- 숫자는 넣어도 되고 안 넣어도 된다. 185편에서 차이가 없었다. 넣으면 본문과 맞는지 반드시 대조한다.
- 제목에 넣지 않는 것: 비유·말장난·감성 문장(첫 문단으로 내린다), 직접 지은 이름만 단독으로(무엇인지 일반 명사와 함께), "[24기 ○○]"·"[2주차 과제]" 같은 머리말, 시리즈 번호.
- `site:gpters.org 도구명 작업`으로 같은 조합 글이 있으면 대상이나 작업 명사를 튼다.
- 새 도구·새 기능이면 제목 하나는 "○○ 사용법" 또는 "○○ 연동하기"로 만든다. 경쟁 글이 없을 때 빨리 쓰는 글이 이긴다.

```
❌ 선풍기에 영혼 불어넣기
❌ [23기 내업무에이전트] 2주차 과제: AI한테 작업 기록을 남겼더니
⭕ 헤르메스에 제미나이 노트북 연동하기
⭕ 클로드 코드로 네이버 부동산 시세 지도 만들기: 770개 단지를 한 장에
⭕ 코덱스와 블렌더 MCP로 한옥카페 3D 미리 보기
```

수요가 안 잡히면 그 자리에서 말하고 도구명을 앞세운 대안을 낸다. 그래도 없으면 **기록형**으로 표시하고 넘어간다(`references/rules.md` 6절).

### 3-3. 빈 칸만 묻는다

재료표를 보여주고, 빈 칸과 확인할 것만 한 번에 묻는다. 세션에서 다 찾았으면 제목 고르기와 "전에는 얼마나"만 남는다.

```
세션에서 이렇게 찾았어요. 틀린 것만 고쳐 주세요.
  처음 요청:   "(원문)"
  막힌 순간:   (에러나 AI 답 원문) → 바꾼 한 마디: "(원문)"
  숫자:       (잰 것 목록)
  시간·비용:   (찾은 것)
  모델:       (찾은 것)
  결과물:     (링크·파일)
  아직 안 된 것: (찾은 것)

빈 칸만 알려 주세요.
1. 이 중 어떤 제목이 제일 가까워요?                  → (제목 3개) + 직접 쓰기
2. AI 쓰기 전에는 얼마나 걸렸어요?                    → 모르면 비워도 돼요
3. (빈 칸이 있을 때만) 쓴 돈이나 요금제, 결과물 링크, 아직 안 된 것
4. 이 세 장면을 찍어서 파일 경로만 알려 주세요.        → (장면 3개) + "못 찍어요" 가능
5. 처음 써 본 사람 반응이 있었어요? (가족, 동료, 손님)  → 없으면 넘어가요
6. 이번 글도 "(프로필 입장 한 줄)" 입장으로 쓸까요?
7. 지난 주에 이어 쓰는 글이면 그 글 주소, 참고한 자료(공식 문서·강의·멤버 글)가 있으면 알려 주세요.
```

- 전부 "알아서 해줘"여도 진행한다. 제목은 1번 후보, 숫자는 세션 값, 입장은 프로필.
- 비운 숫자는 지어내지 않고 그 숫자 없이 쓴다. 기대치는 "기대"라고 쓴다.
- 공개 여부를 본인이 정할 숫자(매출, 수입, 회사 내부 수치)는 `references/rules.md` 3절대로 한 번 묻는다.
- 결과물이 스터디 단톡방·스터디 제공 파일에 기대면 "외부 독자는 이걸 못 봐요. 무엇이었는지 한 줄로 적을까요?"를 묻는다.
- 지난 글은 `fetch-member-posts.mjs`로 가져온 목록에 있으면 제목을 보여주며 확인만 받는다.

### 3-4. 이미지

목표는 실제 화면 캡처 1장 이상. 185편에서 이미지 수는 검색 성과와 상관이 없었다. 이미지는 독자가 결과를 믿게 하는 용도다. 못 채워도 발행은 막지 않는다. 작업 폴더는 `./case-post-images/`.

**① 실제 캡처 + 가리기 (늘 한다)**

멤버가 준 캡처를 열어 본다. 가릴 후보를 찾아 번호로 묻는다. "① 왼쪽 위 폴더 경로 ② 오른쪽 거래처 이름, 이 두 곳 가릴까요?" 승인받은 곳만 가린다.

```bash
python3 <skill>/scripts/blur-region.py 원본.png ./case-post-images/결과.png --blur x,y,w,h [--blur ...] [--crop-top N]
```

가리는 것과 가리지 않는 것은 `references/rules.md` 2절. 가린 결과를 다시 열어 "이렇게 가렸어요"로 보여준다. Pillow·ImageMagick이 없으면 가릴 위치를 말로 알려주고 직접 가려 달라고 한다.

**② 숫자 비교·흐름 카드 (playwright가 있을 때만)**

전후 숫자가 분명하면 카드 1장을 만든다. `references/tpl-compare.html`(숫자 두 개 비교)이나 `references/tpl-two-roles.html`(둘로 나누기)을 복사해 숫자와 한 줄 문구만 바꾼다.

```bash
mkdir -p ./case-post-images && cp <skill>/references/_diagram.css ./case-post-images/
# ./case-post-images/card-1.html 작성 (.stage 안에 도식)
node <skill>/scripts/capture-card.mjs ./case-post-images/card-1.html   # → card-1.png (여백 제거, @2x)
```

- 세로 한 열, 폭 520~560px, 글자 28px 이상, 한 장에 생각 하나(30자 이내, 5줄 이내).
- 도구가 낯선 독자용 개념 도식이 필요하면 `references/eli5-template.html`을 복사해 제목·상자·설명 세 줄만 바꾼다.
- 만든 PNG는 열어서 글자 깨짐·줄바꿈을 눈으로 본다.

**모든 이미지에**: alt 한 줄(숫자나 도구명이 들어가게, "스크린샷"만 쓰지 않는다)과 본문 캡션 한 줄("그림 1. 정정 전후 인식률, 14%에서 75%"). 이미지 속 숫자는 본문 문장에도 쓴다.

### 3-5. 초안 작성

읽는 순서: `~/.gpters/write-post/voice.md`(없으면 `references/voice-default.md`) → `references/best-cases-185.md` → `references/seo-geo-brief.md` 1·2·4·5·7절 → `references/post-templates.md`에서 구성 하나.

**검색을 위한 자리 (제목과 첫 문단)**

- **제목**: 3-3에서 고른 것. H1은 이것 하나뿐.
- **첫 문장**: "[도구A]를 [도구B]에 연결해 [결과물]을 만들었어요" 꼴. 검색어가 그대로 문장이 된다. 영문 표기는 여기서 괄호로: "클로드 코드(Claude Code)".
- **첫 150자**: 첫 문장 + 숫자 하나 + 본문 안 절대 날짜("2026년 9월 23일 기준"). 같은 뜻의 검색어(크롤링/수집, 자동화/연동)를 한 번. 새 도구면 "○○는 ○○하는 도구예요" 정의 한 줄. 인사말, 작성자 소개, 스터디 안내는 두지 않는다. 이 구간이 검색 결과 설명문이 되고 발행 후 못 바꾼다.
- **재미있는 한 줄은 첫 문단 둘째 줄부터.** 제목에서 뺀 비유나 감성 문장이 들어갈 자리다.

**사람을 위한 본문**

- **작성자의 사정을 끝까지 잇는다.** 첫 H2 뒤 작성자 줄(`author_line`)에서 시작한 사정이 막힌 순간과 결과에서 다시 나온다. 고양이 이름, 가게 손님, 팀원의 반응처럼 구체적으로.
- **요청은 원문 그대로 코드블록에.** 재료표의 처음 요청과 바꾼 한 마디를 다듬지 않고 넣는다. 오타도 살린다. 개인정보만 가린다.
- **막힌 순간은 감정 한 줄 + 원문 + 바꾼 것 + 결과.** 시도 횟수를 셌으면 센다("세 번째도 안 됐어요").
- **AI 출력은 5줄 이하로 인용.** 길면 핵심 줄만 인용하고 나머지는 "(뒤로 표가 40줄 더 이어져요)"처럼 말로.
- **결과는 이미지 없이도 읽히게.** 링크 + 두 줄 묘사.
- **"아직 안 된 것"을 쓴다.** 소제목으로 세우거나 결과 섹션 끝에 한두 줄. 없다고 하면 "지금 쓰면서 불편한 점"이라도.
- **앞으로의 계획은 결과보다 짧게.** 한두 줄이면 된다. 없으면 안 쓴다.
- **소제목(H2)은 그 글의 내용으로.** 틀 이름만 달랑 쓰지 않는다. 게시판 기본 틀(소개 / 진행 방법 / 결과와 배운 점)을 쓰면 "소개: 가계부를 슬랙으로 기록하고 싶었던 이유"처럼 내용을 붙인다.
- **이어 쓰는 글이면** 첫 H2 아래 "N주차 과제로, 지난주 [지난 글 제목](주소)에서 만든 ○○에 △△를 붙였어요" 한두 줄, 그다음 이번 주에 달라진 것부터. 다음 편 예고·전체 편수는 쓰지 않는다.
- **끝**: 따라 할 프롬프트 1개(인용문, [바꿀 부분] 표시) 또는 3~5단계 순서. 참고한 자료가 있으면 `## 참고한 자료`(항목마다 가져온 것 한 줄). 없으면 만들지 않는다.

**쓰지 않는 것**

- 교훈 격언으로 맺기: "A와 B는 다르다", "결국 기술의 본질은". 185편 중 26편에 있었다. 배운 점은 그 글에서 실제로 일어난 일로 쓴다.
- 3인칭·AI 시점: "사용자가 물었다", "이유를 물었더니 답은", "○○님이 말씀하신". 이 글은 작성자가 1인칭으로 쓴다.
- 채움 섹션: "다른 업무에 적용한다면?", "이런 분들께 추천", "배워서 남 주기".
- 근거 없는 숫자와 과장: ROI, 정확도 %, "완전 무인", "10배 빨라짐". 잰 것만.
- 자리표시와 안내문: "[이미지 1]", "📸 여기에", "(내용 입력)", "Tip:", 게시판 양식 질문. 이미지 위치는 발행 메모(3-7)에만 적는다.
- 줄표, 물결표 범위, 3열 이상 표, 첫째·둘째, 헤지, 남이 못 여는 링크, 사용자 이름 든 경로, 서버 IP.

`./AI_CASE_STUDY.md`로 저장한다. **이 파일에는 게시판에 올릴 본문만 둔다.** 태그, 이미지 위치, 올리는 방법 같은 메모는 넣지 않는다(베스트 사례에 "게시판 업로드 안내"가 그대로 발행된 글이 있었다).

### 3-6. 게이트

python이 있으면:

```bash
python3 <skill>/scripts/check-gate.py ./AI_CASE_STUDY.md --keyword "<도구명 한글>" --keyword-en "<영문>" --author "<닉네임>"
python3 <skill>/scripts/check-ai-tell.py ./AI_CASE_STUDY.md
```

`[막힘]`이 0개가 될 때까지 고치고 다시 돌린다. `[주의]`는 멤버에게 알리기만 한다. python이 없으면 `references/rules.md` 4절·4-1절을 한 줄씩 직접 대조하고 "자동 검사 대신 직접 확인했어요"라고 말한다.

playwright가 있으면 폰 화면으로도 찍어 본다.

```bash
node <skill>/scripts/preview-mobile.mjs ./AI_CASE_STUDY.md --width 390
```

그다음 스킬이 직접 대조하고, 결과를 멤버에게 보여준다.

```
[ ] 숫자 대조: 제목·첫 문단·본문·표·캡션에 나온 같은 숫자가 다 같은가 (시간, 건수, 인원, 금액)
[ ] 제목이 약속한 것(연동하기, 사용법, 만들기)을 본문이 실제로 보여주나
[ ] 재료 여덟 가지 중 빠진 것 (빠졌으면 무엇이 빠졌는지만 알린다)
[ ] 요청 원문이 다듬어지지 않았나 (재료표와 대조)
[ ] 이미지 속에 경로·이메일·키·IP·남의 이름이 안 보이나 (이미지 목록을 같이 보여준다)
```

### 3-7. 마무리

`./발행메모.md`를 따로 만들고 대화창에도 보여준다. 본문 파일에는 넣지 않는다.

- **검색 결과 설명문**: 초안 첫 150자. "이 부분이 검색 결과 설명문이 돼요. 발행 후엔 못 바꿔요."
- **태그**: 프로필의 `cohort_tag`(예: `24기 GEO실험실`)는 필수. 이미 게시판에 만들어져 있으니 목록에서 고른다. 도구명 태그를 한글·영문으로 2~4개(`클로드 코드`, `Claude Code`). 새 태그를 만들기 전에 같은 표기가 있는지 먼저 검색한다.
- **게시판**: 스터디 안내에 정해진 곳. 없으면 글 주제에 맞는 곳.
- **이미지**: 파일 목록, 들어갈 위치(어느 소제목 아래), alt 문장. 못 찍은 장면이 있으면 "찍으면 좋을 장면".
- **건너뛴 것**: 검색 조사, 자동 게이트, 카드 중 못 한 것.
- **올리는 방법**:

```
1. AI_CASE_STUDY.md 파일에서 마우스 우클릭 → "미리보기 열기" (Cmd+Shift+V, 윈도우는 Ctrl+Shift+V)
2. 미리보기 화면에서 전체 선택(Cmd+A, Ctrl+A) → 복사
3. 지피터스 글쓰기 화면에 붙여넣기
4. 발행메모의 위치에 이미지 넣고, 대체 텍스트 칸에 alt 문장 넣기
5. 태그 달고 게시
```

- **새 도구라면**: "이 도구는 한국어 글이 아직 적어요. 오늘 올리면 먼저 잡을 수 있어요"라고 알린다.
- "다음 글은 같은 명령으로 시작하면 처음 설정 없이 바로 Phase 1로 가요"로 끝낸다.

## 절대 하지 않는 것

- 검색어를 멤버에게 묻지 않는다. 스킬이 조사해 제목으로 보여준다.
- 숫자를 지어내지 않는다. 세션에 없고 멤버가 비우면 그 숫자 없이 쓴다.
- 없는 경력이나 입장을 지어내지 않는다. 회사명·가게 이름·실명은 본인이 원할 때만.
- 남이 못 여는 링크, 사용자 경로, 키, 남의 개인정보를 본문과 이미지에 남기지 않는다(`references/rules.md` 1~3절).
- 틀 소제목을 쓰지 않는다. 한 주 수백 편이 같은 뼈대가 되면 사이트 전체가 손해를 본다.
- 요청 원문을 다듬지 않는다. 오타와 말투가 사람이 쓴 표시다.
- 본문 파일에 메모·자리표시·안내문을 넣지 않는다. 그런 건 발행메모로.
- 무언가를 설치하라고 먼저 권하지 않는다. 없으면 대체한다.
- 발행하지 않는다. 마무리 안내까지가 이 스킬의 끝이다.
